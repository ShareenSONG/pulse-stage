# 参考视频拆解：本轮XY玩法依据

分析日期：2026-10-20。依据：用户本次提供的本地MP4，即此前小红书笔记的视频。视频约116.84秒，1280×720，含音轨；这是拍摄电视与电脑屏幕的现场视频。本次不另行访问小红书。

方法：先按约5秒间隔抽帧覆盖全片，再检查0/4/10/15/25/35/49/62/72/85/101/115秒的精确取样；对8–9.75、48–49.75、100–101.75秒每250ms检查连续画面。不是逐帧人工标注，不据此推算原游戏的精确判定窗口、BPM或摄像头精度。

## 可观察内容与本作取舍

| 源视频位置 | 可直接观察的画面 | 本作采用方式与证据边界 |
|---|---|---|
| 0秒 | 开头已经是游玩画面；深蓝科技空间、远处菱形装置、近端暖色与青色光点、左下玩家画面 | 舞台为主，摄像头预览缩小；不据此编造参考游戏的授权、选曲或教学流程 |
| 4秒，8–9.75秒连续取样 | 绿色框线/展开光面连续出现，界面有Perfect和Combo | 参考空间层次与节奏反馈；具体是障碍、特殊音符还是舞台反馈未确认，不加入强制躲避/下蹲要求 |
| 10、15、25秒 | 双手不同颜色的光迹、几何块/碎片、连续命中反馈 | 本作重点为双手XY挥击与连续动作衔接；不声称已从画面读出每枚音符的方向要求 |
| 35秒，100–101.75秒 | 圆形/旋纹元素与光效、几何目标、不同位置的轨迹变化 | 参考视觉变化；转轮/画圈的实际判定不明，本轮不加入新评分类型 |
| 48–49.75秒连续取样 | 左右光迹随时间在平面内改变位置，目标与碎裂交替出现，Combo有变化 | 明确输入轨迹与命中反馈的一致性；Combo变化原因不能仅靠抽帧确定，不当作识别精度统计 |
| 62、72、85、101秒 | 同一主要演奏界面持续出现，目标布局变化、左右挥动、即时反馈 | 保持同一读谱规则，依靠乐句编排制造变化；不在一首歌中强制更换玩法 |
| 115秒 | 清晰显示“SONG COMPLETE” | 本作做音乐自然结束→完成提示→本地结算→重试闭环；该帧不能证明参考作品全部结算字段 |

## 本次设计推论

1. 最该还原的是“预读目标→双手移动→到拍挥击→碎裂/评价→接下一枚”的连续体验，而不是同时堆叠双模式、Z、避障和角色系统。
2. 透视纵深用来显示音符接近和时间，不代表玩家需要向镜头前后走动。视频不能证明任何整体Z识别能力，本轮也不要求Z。
3. 颜色区分双手、可见轨迹、集中判定反馈、科技舞台与小预览共同构成主要视觉识别点；不能只把骨架调试面板换个背景。
4. 本作采用约一分钟的64秒原创片段，是本轮验证设计；源视频约117秒，不称它本身为一分钟关卡。
5. 只凭屏幕拍摄不能确认动作端到端延迟、漏检率、精确窗口、原始谱面或内部算法。本作的识别与评分指标必须独立测试。

## 映射到需求v1.3

P0：单一双手XY挥击、一个64秒谱面、上半身定位、双手映射/轨迹/命中、连续取帧、命中反馈、完成/结算/重试、玩家与技术问题分开统计。

暂缓：Z0/Z1、独立Catch模式、保持、转轮、强制避障/下蹲、完整领舞、第二难度、慢速乐句练习、曲库与联网。

素材仅作为用户提供的内部设计参考；不把参考视频或游戏中的音乐、舞台资产直接打包进原型。
