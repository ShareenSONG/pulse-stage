# 《星跃律动》v1.3→v1.4需求变更说明（审核版）

日期：2026-10-21。状态：待用户审核，代码尚未修改。

完整规则：[v1.4身体横移与节拍撞块](./星跃律动_体感节奏游戏需求_v1.4_身体横移节拍撞块_待审核.md)。
视频依据：[新视频拆解与关键帧](./参考视频拆解_身体横移与撞块_20261021.md)。

## 建议的新玩法

**自动前进的飞行器 + 身体左右移动转向 + 音乐拍点撞块 + 短促冲击反馈。**

玩家可以放松双手，像在音乐跑道上驾驶：看到下一组在左边，就用身体向左移动；到拍时飞行器撞碎方块。接着保持吃完同道连拍，再根据下一组的位置回中或右移。

这里采用“提前对位，等方块到拍撞上”，不额外要求拍点挥手或每块重新横移触发。更接近本次视频的载具/跑道/连续撞块体验。身体输入是本作的新方案；视频本身没有证明它使用人体摄像头。

## 与当前Demo的差别

| 项目 | 当前v0.2.0 / 需求v1.3 | v1.4建议 |
|---|---|---|
| 控制对象 | 两只手的光点 | 一个明确的飞行器主体 |
| 动作 | 双手XY挥击 | 身体左右小幅移动或舒适侧倾 |
| 局内所需关节 | 双肩、双肘、双腕 | 可靠双肩；手腕/髋部不足不阻断驾驶 |
| 手的用途 | 主判分点 | 退出撞块评分；菜单/可选暂停仍可用手 |
| 命中时刻 | 手部轨迹在时间窗穿越 | 方块按音乐时间到线，在目标拍检查驾驶位置 |
| 提前到位 | 原挥击要求不能静止刷分 | 合法；等拍点自动相撞，不能提前碎裂 |
| 同道连续块 | 必须有新的挥击动作 | 保持位置，按独立拍点连续撞击；每块只算一次 |
| 评价 | 挥击时间/区域 | 拍点时空间对位，不能再称毫秒挥击精度 |
| 视觉 | 双光标、少量光效 | 跑道、载具倾斜/尾焰、方块碎裂、路面冲击波 |

| 内容规模 | 64秒80手部单位 | 64秒建议60块、约18–24次明显横向换位 |

## 身体换位不会照抄视频里的手速

一组可以有2–4个同道节奏块，每0.5秒撞一个；人只需保持位置。相邻带换位至少留约1秒过渡，两次换位起点建议至少隔2秒，跨左右两端要经过中间并留更长时间。

例如一个8秒短句：中位两拍→左位两拍→中位两拍→右位两拍。视觉与听觉仍是连续的音乐撞击，身体不需要每0.5秒左右猛甩。

## 震动反馈怎么做

普通命中：局部2–3px短震、载具轻压缩、少量碎片、短音。
重拍/连拍组收束：4–6px短震、更明显回弹/冲击波、较饱满短音。

这些是初始视觉参数，不是已测效果。HUD、未命中目标、撞击线和碰撞体不随特效漂移；连拍不无限叠加。Miss不播放成功撞击音/强震动。可选择关闭/轻/标准反馈。

本轮的“震动”是画面冲击感，不把Mac机身/触控板实体振动作为交付。

## 不变与暂缓

保留Mac浏览器、单目摄像头、本地处理、不默认录制、上半身、一首约一分钟音乐、完成/结算/重试，以及跨页面持续取帧。

Z、跳跃/下蹲、必须躲避的尖刺、完整领舞、多人、多曲库和联网仍不扩展。原手部算法/成绩可以保留作历史，不在本轮同时维护第二主玩法。

现有摄像头曾观测约6–15FPS，输入延迟仍要优化；换成身体驾驶不能直接等同于精度与性能已经通过。先做身体驾驶灰盒，再加震动和复杂特效。

## 审核重点

1. 是否采用**身体驾驶单个飞行器**，双手退出局内评分？
2. 是否采用**到拍自动撞击、允许提前对位和同道保持**，而不要求每块额外卡拍侧身触发？
3. 是否接受**可关闭的画面震动+声音冲击反馈**，本轮不要求实体振动？

本文建议采用以上三点；用户确认后再进入代码修改。当前站点与v0.2.0软件保持不变，v1.3仍是已实施基线。
