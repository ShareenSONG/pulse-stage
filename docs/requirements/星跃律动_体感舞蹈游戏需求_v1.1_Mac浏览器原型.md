## 02｜游戏定位与体验目标

一款用真实身体动作演奏音乐的轻舞蹈节奏游戏。玩家通过接拍、挥切、双手动作、侧摆和小幅前后移动完成连续舞段。

三项核心体验：

1. **跟得上**：镜子式手部映射、大目标区、提前预读、简短教学。
2. **打得爽**：音符到拍清楚，动作反馈直接，光刃和音效随成功触发。
3. **动得顺**：动作按 4/8 拍乐句组织，包含准备、发力和恢复，避免只用手腕刷分。

本轮需要回答：只靠 RGB 摄像头是否足以支撑玩法？Z 是否增加舞动感？指定前后方向的收益是否超过识别错误和空间负担？科技舞台是否在提升爽感的同时保持清晰？

## 03｜原型结构与可玩模式

| 模式 | 目的 | 最小功能 | 优先级 |
|---|---|---|---|
| 动作测试场 | 独立验证输入 | 摄像头预览、骨架、双手轨迹、Z 信号、方向/不确定、置信度、事件日志 | P0 |
| 快速开跳 | 验证游戏闭环 | 约 60 秒关卡、教学、计时评分、Combo、暂停、结算与重试 | P0 |
| Z 对照试玩 | 比较不同能力 | 同一音频与手部舞段，三种 Z 配置，记录成功率和反馈 | P0 |
| 舞段练习 | 定位识别或编排问题 | 重播 32 秒段、指定乐句、无成绩压力 | P1 |

### 3.1 三种动作配置

- `XY` 原地律动：Z 位置用预先编排的双手接拍替代，验证基础玩法。
- `Z0` 空间脉冲：在目标拍完成一次小幅前后移动，向前或向后均可。
- `Z1` 前后律动实验：在目标拍完成指定的靠近或远离；不确定时不能猜测成功或错误方向。

三种配置独立保存成绩和识别统计。Z1 初始标为实验能力，在测试场完成相应校准后开放独立试玩；校准不通过也应给出原因报告，不能以隐藏入口掩盖未完成的验证。

当前一个基础难度即可完整交付；第二档节奏强度为 P1，三档完整难度留待产品阶段。

## 04｜Mac 运行环境与设备要求

### 4.1 默认运行方式

在 Mac 启动本地服务，用桌面浏览器访问 `localhost`。浏览器请求摄像头权限，在本机执行姿态识别、动作分析、音频和图形渲染，不上传原始视频。

本轮优先验证当前 Mac 上的 Chrome 稳定版本，记录实际浏览器、系统和模型版本；Safari 的兼容性作为后续检查项，不将未经测试的浏览器写入支持名单。

技术选型基线为 TypeScript、Vite、MediaPipe Tasks Vision、Web Audio、Three.js/WebGL。它们是本轮实现建议，依赖版本应在开发开始时验证并锁定；识别放入 Worker，UI 与舞台留在主线程。无需安卓模拟器、手机或外部游戏机。

摄像头页面须运行于 localhost 或 HTTPS；权限拒绝、摄像头被其他应用占用、模型资源加载失败均有恢复路径。浏览器摄像头权限和音频启动按其用户交互要求实现，不能假定打开页面就能自动播放音乐。[摄像头 API 说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

### 4.2 摆放与显示

- Mac 固定在稳定平面，开局后不调整机身和屏幕角度。
- 玩家保持正面，确保抬手、侧摆和小步前后移动时仍在取景范围内。
- 不启用会改变有效取景尺度的人物自动跟随、自动变焦或动态裁切；若不能确认关闭，对 Z 测试标注限制。
- 默认 Mac 屏幕显示，可选有线外接电视；外接后单独校准视听链路。
- 原型不默认使用无线投屏、蓝牙音频或手机连续互通相机作为基准输入/输出，避免引入额外变量。
- 不强制固定站距；约 2–3 米仅是试摆起点，以玩家完整动作入框和清晰可读为准。

### 4.3 操作边界

第一次启动、浏览器授权和调试可用鼠标键盘。完成启动后，选配置、开始、暂停、结算和重试支持裸手闭环；同时保留 Esc 暂停与点击操作，便于开发测试。

键盘模拟输入必须明显标为“模拟输入”，只能检验谱面和反馈，不能作为真实摄像头识别通过的证据。

## 05｜站位与三档 Z 校准

| 步骤 | 玩家动作 | 输出与成功条件 | 失败处理 |
|---|---|---|---|
| 摄像头准备 | 选择镜头并授权 | 摄像头与模型正常，实际帧尺寸可见 | 重试、换镜头、查看权限说明 |
| 人体锁定 | 正面站稳约 2 秒 | 主玩家、关节置信度、原始画面尺度 | 提示补光/调整站位 |
| 舒适范围 | 抬手、左右伸展、轻侧摆 | 手部触达范围及静态噪声 | 重校准，缩小目标范围 |
| 左右确认 | 跟随示范举左手、右手 | 镜像与解剖学左右一致 | 修正显示映射后复验 |
| Z0 校准 | 小幅前后动 3 次，每次停稳 | 能稳定识别运动事件且静止不误触发 | 保留 XY，显示 Z0 未通过 |
| Z1 校准 | 在提示下分别靠近/远离各 3–5 次 | 得到两方向分布、置信度、混淆与拒判情况 | Z0 可继续，Z1 标注待改进 |
| 音画/动作同步 | 跟随 8–12 个拍点 | 当前设备链路综合偏差 | 重试或使用临时偏移并标注 |

Z1 的校准真值来自测试指令与人工核验；不能把系统自己的预测当真值。校准通过只证明当前人的当前场景可进入测试，不等于多人多环境准确率已达标。

保存两类独立数据：用于手部映射的身体相对坐标，以及用于整体纵深分析的原始图像尺度与变化历史。不能先把每帧人体统一缩放，再用已归一化尺寸判断前后。

更换玩家、镜头、机身位置或裁切后重校准。Z1 单次试验内冻结参考基线，防止前进被自动重设为新原点；重新设定原点只能在明确的重置阶段执行并记录。

## 06｜动作字典与基础判定

| ID | 音符 | 动作 | 最小判定依据 | 原型范围 |
|---|---|---|---|---|
| A01 | 接拍 | 指定手进入目标区 | 手腕有效进入+短暂确认 | P0 |
| A02 | 挥切 | 按 XY 箭头切过目标 | 轨迹穿越、方向与幅度 | P0 |
| A03 | 双手拍 | 两手分别到达目标 | 两个独立手事件 | P0 |
| A04 | 延音 | 手随路径移动 | 有效覆盖时间 | P1 |
| A05 | 侧摆 | 躯干轻侧移/侧倾 | 肩髋横向变化及姿态约束 | P0 |
| A06 | 纵深脉冲 | 前后动一下，任意方向 | Z0 无方向整体位移事件 | P0 |
| A08 | 靠近拍 | 身体向镜头小幅移动 | Z1 有方向事件 `toward_camera` | P0 实验 |
| A09 | 远离拍 | 身体离镜头小幅移动 | Z1 有方向事件 `away_from_camera` | P0 实验 |
| A07 | 低位律动 | 轻屈膝 | 髋下降与膝姿态 | 暂缓，作为混淆负样本 |

接拍：需要进入目标或从待机区重新移动到目标，不能长期预放手得分。初始确认时长 60–100ms，确认后用首次进入时间计时。

挥切：用连续有效手腕采样构成的线段与区域求交，避免快挥漏判；初始 XY 方向容差 ±45°。长时间失踪后的跨区连线不算有效挥切。

双手拍：两手时间差初始 ≤120ms，整枚评价取较低档；只命中一手可得半分但整枚记 Miss 并断连。不得用单手快速跨区替代双手。

延音：一枚只结算一次；覆盖率初始 ≥90%/75%/50% 对应 Perfect/Great/Good，首尾需同时合格，短抖动约 100ms 宽限。P1 完成后独立验收。

侧摆与 Z 在首轮谱面中错开。大幅运动不额外加分，脚步动画和角色表情不作为隐藏判分依据。

## 07｜Z 识别：共同原则与两档能力

### 7.1 可实现性与限制

固定单目摄像头可以利用同一玩家在连续画面中的表观尺度、身体关键点和运动趋势，估计是否发生整体前后移动，进一步尝试区分靠近或远离。这里是工程方案和待验证假设，不承诺任意姿态、任意光照均可靠。

在近似针孔成像、同一人保持近似正面且姿态变化较小的条件下，图像尺度与距离近似成反比。若尺度从 s0 变为 s，可用 `相对距离比例 ≈ s0/s` 构建粗略特征；该值不等于厘米，不可在显著转身、屈膝或动态裁切时直接使用。

MediaPipe 的关节深度与世界关节坐标以髋部中点为原点。因此，要另行分析整个人相对摄像头的移动，不能直接用髋部关节 z 或“手比髋部靠前”替代整体平移。[坐标定义](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

### 7.2 共同处理管线

原始图像坐标 → 多关节置信度检查 → 正面/弯腰/屈膝等姿态质量检查 → 多部位尺度与运动趋势 → 时间滤波与迟滞 → 候选事件 → 持续性确认 → Z0/Z1 输出。

可融合肩宽、髋宽、躯干相关距离和人体局部光流，但不以单一人体框或单一肩宽下结论。模型裁切 ROI 变化、摄像头移动和自动取景均需排查；本轮无法可靠检测的情况通过固定摆放、关闭功能和测试记录控制，不能声称系统能自动识别所有相机扰动。

真实靠近/远离为正样本；静止、挥臂、扩胸、弯腰、侧转、横移、屈膝、手前伸、镜头变化与其他人入镜为负样本或必须拒判的条件。

### 7.3 Z0：无方向空间脉冲

- 输出 `DepthPulse`：只表达发生了合格整体前后移动，不带方向条件。
- 玩家用语：“身体前后轻轻动一下，向前、向后都可以。”
- 使用对称双环/身体图标，成功播放固定能量扩散或空间展开。
- Z0 不依赖 Z1 先得出方向：方向证据不足、但整体纵深证据足够时仍可能输出 Z0；整体证据也不足则拒判。
- 只知道无方向运动时不能证明回到物理原点；回位是引导，停稳不等于回原点。

### 7.4 Z1：有方向前后律动实验

- 输出 `DepthStep`，方向仅可为 `toward_camera` 或 `away_from_camera`；证据不足输出诊断状态 `uncertain`，不生成可评分方向事件。
- 明确玩家语义：“靠近摄像头/屏幕一步”“远离摄像头/屏幕一步”。当前默认屏幕与镜头同侧；改变摆放时先改教学，不能沿用含混的游戏世界前后。
- 靠近拍用向中心聚合的门形符号与“靠近”文字，远离拍用向外退开的门形符号与“远离”文字。不能只靠透视大小和颜色区别。
- 只有整体移动、方向和置信度均合格才消费音符；不要从谱面预期方向反推识别结果。
- 动作方向可被估计，不代表能准确获得当前位置。首版不做连续自由 Z 移动控制，也不做精确距离门槛。
- 相对站位指标可用于“接近初始范围”的辅助提示，须标注估计；它不能作为已经证明回到精确物理原点的依据。

### 7.5 状态机与回位

`未就绪 → 稳定约300ms → 可触发 → 候选 → 持续确认约100–180ms → 输出一次 → 恢复锁定 → 再次稳定`

共同要求：进入阈值高于退出阈值；动作事件唯一 ID；确认后回溯首次满足条件的采集时间；初始恢复锁定至少约 800ms，且谱面恢复空段未结束时不重新计分；持续摇摆和持续走动不能定时自动连发。

游戏同一动作最多消费一个事件。测试场允许显示动作和回程两个物理运动片段，但需要标注所属试验和阶段；游戏回位阶段的运动不得产生额外得分。

Z1 错方向后仍进入本次试验恢复阶段，不能立刻反向修正刷同一枚音符。下一次动作需等待稳定和新提示。

### 7.6 Z 谱面约束

1. 初版两个 Z 计分点至少相隔 3 秒，编辑器按毫秒检查。
2. 普通 Z 提示至少提前 2 秒，新手建议 3 秒；方向提示必须足够早让玩家理解。
3. 初始在 Z 判定前 500ms、后至少 1000ms 清空强制手部音符、侧摆和延音；实际回位更慢则延长空段。
4. Z1 从舒适中心发起小步动作，在非计分空段回位；不连续要求多次同向移动，不允许累计后退。
5. 单段 Z 只在乐句重拍使用，建议占评分单位约 5%–10%；32 秒控制段可为实验目的单独标记密度。
6. 不提高步幅来强行弥补不稳定识别。若安全的小幅动作不能识别，记录失败并调整方案。

### 7.7 降级与不确定

曲前校准不通过：给出问题 → 重试或主动选低一级配置。Z1 可以切 Z0，Z0 可以切 XY，切换后加载独立谱面。

演奏中不静默切换配置。出现不确定事件时先显示短提示，当前音符进入系统保护；持续低质量约 300ms 或关键输入失效时暂停。重校准后继续为辅助成绩，或者从头重开原配置。

实验评估必须保留全部不确定、未输出和错方向样本，不能只报告系统愿意作答的样本准确率。

## 08｜舞段编排与对照内容

### 8.1 约一分钟基础关卡

采用节拍清楚的自有、合成或已授权音乐，建议先固定 120 BPM、4/4 拍，约 60 秒。包含左右接拍、挥切、双手拍、侧摆和 4–6 个 Z 节点；节点数量服从实际恢复空段。

以 4/8 拍组织短句：重复 → 变化 → 重拍 → 恢复。XY/Z0/Z1 采用相同音频、手部舞段和匹配的 Z 时点，使体验可对照；XY 在 Z 节点使用双手替代。

Z1 安排靠近与远离数量平衡，顺序变化以避免系统或玩家只凭交替规律猜答案。每次方向动作后明确留出非评分回位时间。

### 8.2 32 秒控制段：120 BPM，16 小节

| 小节 | 起点 | 所有配置共同内容 | XY / Z0 / Z1 差异 |
|---|---:|---|---|
| 1–2 | 0s | 左右中位接拍 | 无 |
| 3–4 | 4s | 左上、右下挥切 | 无 |
| 5 | 8s | 休止与下一动作预提示 | 显示各配置动作 |
| 6 | 10s | 第1拍特殊动作，之后回位空段 | 双手拍 / 任意纵深 / 靠近 |
| 7–8 | 12s | 重复挥切短句 | 无 |
| 9–10 | 16s | 侧摆与简单接拍，错开判定 | 无 |
| 11 | 20s | 休止与下一动作预提示 | 显示各配置动作 |
| 12 | 22s | 第1拍特殊动作，之后回位空段 | 双手拍 / 任意纵深 / 远离 |
| 13–14 | 24s | 手部重复与少量位置变化 | 无 |
| 15–16 | 28s | 双手收尾 | 无 |

另做反向顺序 Z1 版本，用于排除固定顺序效应。本段只含少量 Z，不足以替代专门的方向识别样本测试。

## 09｜评分、公平性与音频时间轴

### 9.1 原型判定窗口

| 评价 | 接拍/挥切时间误差 | 侧摆/Z0/Z1 时间误差 | 分数系数 |
|---|---:|---:|---:|
| Perfect | ≤90ms | ≤160ms | 1.00 |
| Great | >90–150ms | >160–260ms | 0.80 |
| Good | >150–230ms | >260–380ms | 0.50 |
| Miss | 超窗/动作不合格 | 超窗/动作不合格 | 0 |

Z1 方向明确但相反为 Wrong Direction，按 Miss 结算；方向不确定或输入技术失效为 System Protected，不当作普通 Wrong Direction，也不自动补成功。底层诊断仍保留拒判，用于算法评估。

`总分 = round(1,000,000 × Σ(权重 × 实得系数) / Σ(谱面全部权重))`

默认每枚权重 1。Perfect/Great 增加 Combo，Good 有分断连，Miss 断连；Combo 不再乘分。评级建议 S≥95%、A≥85%、B≥70%、C≥50%、D<50%。

系统保护音符暂不加分且保留原分母，不因拒判而抬高准确率；单列保护数，当前局标注辅助成绩，不覆盖正式最佳。不同配置、谱面版本、评分规则与模拟输入不混榜。

### 9.2 时间基准

以 Web Audio 音频时间为主轴。帧采集/呈现时间、识别开始/结束、候选开始与事件确认分别记录；建立视频时间到单调时钟再到音频时间的映射，并记录采用的时间戳来源与浏览器可观测限制。

评分使用映射后的候选起始时间，不使用 Worker 回传结果的到达时刻。候选起始判据要与人工标注定义一致；Z0/Z1 的确认延迟单独测量。

Web Audio 输出时间、视频时间与浏览器单调时钟不能直接假定相等；暂停、音频上下文挂起和继续后需重建或检查映射。原型同机运行不需要手机主机网络同步。

初版使用有界最终结算缓冲：建议手部约 200ms、Z 约 350ms，需结合实测确认；到拍时可先给临时反馈，确认后才写最终评分。超过缓冲按技术保护处理，不伪造时间戳。缓冲是容纳计算确认的时间，不是额外放宽玩家动作窗口。

综合校准偏移仅补偿一次，不能同时减去已包含的摄像头、确认与输出延迟。外接屏幕、切换音频设备或浏览器恢复后需复验。

### 9.3 去重、暂停与恢复

事件与音符一对一消费；同类型、同手、区域有效的候选优先匹配时间差最小音符，同差值取较早音符。恢复轨迹、回程动作和重复消息不得重复加分。

暂停冻结音频与谱面，清空过期动作。恢复需重新锁定人体并倒数，可从安全乐句重播；重播区间旧成绩作废后重算。中途暂停、系统保护或动态辅助均标辅助局，正式最佳需要完整原速无中断完成。

### 10.2 导航规范

手腕光标指向大按钮，稳定停留约 1 秒确认并显示进度；离开取消，短暂抖动可容错。演奏关闭菜单光标。

主动暂停候选手势为双腕在头部以上窄区保持约 1.5 秒，谱面不安排同姿势长停留；需测试举手音符误触。Esc 与点击暂停始终保留，算法失效自动暂停不依赖手势。

调试面板默认仅测试场或主动打开时显示；演奏页不堆叠阈值、骨架数值和性能图，保留清晰玩家体验。

## 11｜科技未来感美术规范

### 11.1 视觉方向：未来光轨竞技舞台

明确采用用户指定的 Starri 科技未来感参考：深色空间、远近透视、悬浮几何音符、发光切线、能量粒子、金属/半透明舞台装置和风格化表演角色。

“未来感”落在可制作的元素上：远处舞台核心、两侧透视光轨、稳定击中面、手部短光刃、Z 能量门、连击激活的舞台层。不是把画面变成密集仪表盘。

用户选定的科幻方向优先；采用青蓝/紫色空间光和高饱和特效是有意参考，不为套用通用商务界面规范而移除。高亮集中在音符、动作与成功瞬间，读谱平面保持安静。

### 11.2 色彩、形状与材质建议

| 角色 | 建议色值 | 用法 |
|---|---|---|
| 深空底色 | #080D1C | 主舞台背景，低亮度 |
| 空间辅光 | #6556D9 | 远处装置、切景和环境光，不盖住目标 |
| 左手主色 | #50D9F5 | 圆芯/左标记与短光刃 |
| 右手主色 | #FF85B9 | 菱形/右标记与短光刃 |
| Z0 | #FFE39B | 对称双环，能量扩散 |
| Z1 靠近 | #A5F4D1 | 向内门形+“靠近” |

| 正文/Perfect | #F4F7FF | 清晰实体文字，不做发光细字 |

手别与方向均用颜色+形状+文字重复编码，不能只靠颜色。左右手和 Z 的形状需在低特效、灰度和静止图例里仍能区分。

舞台可用程序化 WebGL 几何实现有意义的光轨、装置和能量环；这些就是游戏场景资产，不使用无关图片填充。原型先完成一套原创舞台，不复刻 Starri 角色、界面或资源。

### 11.3 布局与动效

- 16:9 为关卡设计基准，Mac 非 16:9 窗口居中适配；不拉伸相机输入，不因窗口变化破坏手部映射。
- 中央约 65%–75% 是主要读谱区，左/右高、中、低六区；初始难度以中部四区为主。
- 音符沿透视轨道接近固定击中面。音符视觉 Z 主要表示时间，不冒充玩家真实距离。
- 普通音符提前约 1.5–2 秒可读；Z 提示固定于主视线附近，至少提前 2 秒；不被角色挡住。
- 背景光轨可以随音乐变化，击中面和输入映射不能随装饰相机漂移。
- 手部短尾迹即时跟随；挥切 120–180ms 碎片反馈；Z0 300–500ms 扩散；Z1 用已确认方向触发靠近聚合/远离释放的预设反馈。
- 不把角色连续前后走位当精确捕捉演示；Z1 初版只做离散方向事件反馈。
- Combo 放在上方外围，判定文字不得覆盖下一枚目标；背景切景不在高密度段发生。
- 标准版有完整科技舞台，低特效版去掉屏震、强粒子和大范围闪光，保留音符与方向图示；拒绝频闪作为必要提示。

### 11.4 原型资产清单

P0：一套未来舞台、接拍/挥切/双手/侧摆/Z0/靠近/远离音符、左右光刃、Perfect/Great/Good/Miss/不确定反馈、教学动作示意、统一按钮与结算版式。

P1：一个原创风格化角色或简化运动化身、上身受约束跟随、脚部预设动画。角色系统不阻塞 P0；没有正式角色时用明确设计的身体能量轮廓，不用灰色占位框。

字体使用已确认许可的清晰字体，显示文字和数字分层；Mac 窗口和有线电视两种观看距离都需验收。导航正文以对比度 ≥4.5:1 为目标，重要图形边界 ≥3:1。按钮具有普通、指向、停留、触发、不可用、加载和错误状态。

## 12｜音频、谱面与数据配置

### 12.1 内容最小集

- 一段约 60 秒的自有/合成/已授权音乐，用于正式可玩原型。
- 一个 32 秒控制段及方向顺序变体，可从同源素材裁取。
- XY/Z0/Z1 三种配置，每种真实运行并独立检查；不要求 12 首曲库。
- 音乐与反馈音独立音量；不能只交付节拍器加骨架调试画面。

### 12.2 配置文件

歌曲：ID、音频文件/校验、时长、BPM/变速表、拍号、起拍偏移、素材来源。

谱面：ID/版本、音乐 ID、配置 `XY/Z0/Z1`、规则版本、事件、预提示、恢复空段、舞台事件轨、输入与实验标识。

音符：唯一 ID、音频目标时间、类型、指定手、归一化 XY、半径、挥切方向、权重、可选时长。`DepthPulse` 无方向；`DepthStep` 必须明确 `toward_camera` 或 `away_from_camera`。禁止把虚拟镜头方向写进识别字段。

本轮用可编辑 JSON 加谱面预览与校验脚本即可，不要求完整可视化编辑器。校验必须检查类型、版本、音频时长、Z 间隔、预提示、恢复空段、同手不可达跳变和冲突。

### 12.3 本地运行与离线

开发初次安装依赖和下载模型可需要网络。交付版的运行依赖、模型、音频、字体和舞台资产打包到本地，本地服务启动后不依赖 CDN；断公网可以完成完整游玩。离线不等于直接双击 `file://` 页面。

## 13｜浏览器技术架构与数据契约

### 13.1 模块边界

`摄像头 → 视频帧/时间戳 → Worker 姿态推理 → 动作特征与 Z0/Z1 → 音频时间映射 → 谱面匹配 → 分数/光效 → 本地结果`

主线程维护页面、Web Audio 主时间轴和 Three.js 舞台；Worker 处理模型推理与较重特征分析。帧传递采用有界队列，处理不过来时丢弃过时待处理帧并记录，不堆积无限延迟；持续性能不足触发暂停。

视频只采集一次，测试场预览和推理共享同源输入；不为每个模式重复开启多个摄像头流。输入、特征、事件、判分、渲染分层，未来安卓可替换采集和推理适配层，保留谱面与规则语义。

### 13.2 数据契约

| 数据 | 必需字段 |
|---|---|
| 姿态帧 | 会话/帧 ID、视频时间、单调时钟映射、关节/可见性、原始尺寸、跟踪质量 |
| Z 特征 | 多部位尺度、稳定基线、变化趋势、姿态质量、排除/拒判原因 |
| Z0 事件 | 唯一 ID、`DepthPulse`、候选开始/确认时间、无符号强度、置信度、试验阶段 |
| Z1 事件 | 唯一 ID、`DepthStep`、相同时间字段、方向、方向置信度、试验 ID；不确定另记状态 |
| 诊断状态 | `stable/moving/uncertain/unavailable`、原因、事件/会话关联 |
| 判分 | 音符/事件 ID、配置/规则版本、最终评价、时间误差、错方向或保护原因 |
| 实验结果 | 人物匿名 ID、真实动作标签、预测/未输出、阶段、模式/光照/衣着、性能统计 |

同一物理动作可以被算法对照地评估 Z0 和 Z1，但游戏只订阅当前配置的一条计分路径，不能对两个输出重复加分。两档的成功率分别统计，不强行认为 Z1 正确就代表全部 Z0 测试已通过。

### 13.3 测试场显示

必须能看见：原始画面与骨架、手轨迹、尺度趋势、基线、当前检测方向/不确定、置信度、恢复锁定、拒判理由、采集/推理/渲染帧率。

测试参数可以修改，但每次参数变化产生配置版本并写入结果。人工标签来自独立指令与观察；调参集与保留验证集不能混用。

## 14｜性能、兼容性与故障处理

### 14.1 初始性能目标

| 指标 | 当前 Mac 原型目标 |
|---|---|
| 相机帧率 | 请求并验证约 30fps，记录实际帧率 |
| 姿态输出 | 常态 ≥25 次/秒；连续约 2 秒低于 20 次/秒提示并暂停正式局 |
| 主舞台渲染 | 目标 60fps；低特效档至少稳定 30fps |
| 手部处理链 | 可测帧时间到事件可用 P95 ≤120ms |
| 动作到可见反馈 | 本机内屏 P95 ≤150ms，外部参考测量；Z 确认时延单报 |
| 校准后时间残差 | 中位绝对误差目标 ≤40ms，P95 ≤80ms；统一测量定义 |
| 连续运行 | 20 分钟循环无崩溃、失控内存增长或持续识别降速 |
| 离线 | 本地资源准备后断公网完整跑完三种配置 |

Web 时间戳不一定暴露完整传感器曝光时间；软件内部处理耗时不能代替端到端延迟。报告需区分可观测软件时间与外部测量结果，未测项明确标注。

先减少背景粒子、光晕和角色复杂度，再调整识别频率或输入规格；更改推理设置后重新验证精度，不静默放宽判分继续比较成绩。

### 14.2 必须处理的异常

摄像头权限拒绝/被占用、设备移除、模型或音频加载失败、暗光/遮挡/出框、其他人入镜、浏览器标签页隐藏、窗口失焦、系统睡眠、音频上下文挂起、输出设备切换、性能不足、存档失败。

输入或音频异常时冻结游戏时间并说明原因；恢复重新锁人和同步。页面离开或停止摄像头时释放流和计算资源。镜头位置变化若无法自动可靠识别，应由用户明确重校准，不假装已有完整检测。

## 15｜隐私、动作安全与数据保存

默认只在本机浏览器处理视频，不上传、不录像、不做人脸身份识别。视频预览可关闭，关闭只隐藏显示，不表示停止识别；停止摄像头按钮必须实际释放输入。

本地保存设置、校准档案、最佳成绩与必要的匿名测试数据；提供清除。原始视频或完整关节时序只在明确开启的测试采集流程里保存，保存前说明用途和范围；默认导出摘要，不自动导出连续人体轨迹。

JSON 导出包含配置版本、聚合指标和经选择的事件记录；可附 CSV 汇总。普通用户流程不要求上传视频或注册账号。

动作保持小幅、低冲击；不奖励更大步幅。向后指令仅在玩家自行确认背后净空、校准通过后展示。单目摄像头不承诺检测地面防滑和完整家具边界，界面不能显示“环境已确认安全”。

## 16｜结算、纪录与后续成长

本轮结算显示：模式/谱面版本、输入类型、总分、准确率、最大连击、Perfect/Great/Good/Miss、Z0 成功数、Z1 靠近/远离成功和错方向数、系统保护数、是否完整完成。

试验诊断另外显示：拒判率、未输出率和技术中断，不在玩家失败提示里堆叠算法术语。玩家可换配置重试，不能把辅助局覆盖正式最佳。

成长币、服装商店、曲包、多角色和每日任务暂缓。本轮重玩动力是个人最佳、清晰反馈和一段能掌握的舞段。

## 17｜Z 对照测试与指标定义

### 17.1 测试步骤

1. 开发自测：验证静止、接拍、挥切、每种负样本与前后各方向事件。
2. 小样本玩法测试：建议 5–8 名不同身高/经验的成人，使用当前 Mac，比较 XY/Z0/Z1；先验证交互和主要误判。
3. 冻结参数后保留验证：建议累计至少 12 名成人且包含至少 4 名未参与调参的人；固定场景与较难光照/衣着分别报告。人数是本轮探索建议，不是量产认证。
4. 每人至少做靠近 20 次、远离 20 次，以及静止和常见混淆动作；不同测试者均覆盖方向，不能用换人后的尺寸差当位移。
5. 三种可玩配置交错测试顺序，避免熟练度只偏向最后一种；记录疲劳、动作自然性、理解难度与主观公平感。

### 17.2 指标定义

| 指标 | 定义 |
|---|---|
| Z0 事件召回 | 被一对一匹配的真实前后移动 / 全部真实前后移动 |
| Z0 事件精确率 | 一对一正确匹配事件 / 所有输出事件；重复事件算额外误报 |
| Z1 全样本方向成功率 | 被正确检测且方向正确的试验 / 全部有效真实方向试验；拒判、漏检均计入分母 |
| Z1 方向作答准确率 | 正确方向事件 / 已匹配且给出方向的真实动作；必须与覆盖率一起报告 |
| Z1 覆盖率 | 有有效方向作答的试验 / 全部真实方向试验 |
| 方向混淆 | 靠近被判远离、远离被判靠近；另列 uncertain、无输出 |
| 负样本误报 | 每类非 Z 动作误报次数 / 该类动作次数；自然舞动另报每分钟误报 |
| 回位重复计分 | 一次计分动作及其回位产生的额外计分次数 |

匹配窗口和人工起始定义在验证前冻结。测试场即使能显示“正确率 100%”，只要大量拒判，不能作为方向玩法可用的结论。

## 18｜验收门槛与结论等级

以下为建议冻结目标。若实测不通过，应保留失败报告和可玩低档，明确本轮尚未验证通过的能力。

| ID | 验收项 | 本轮通过目标 |
|---|---|---|
| AC01 | 可启动 | 当前 Mac 和记录版本的浏览器可按说明本地启动；依赖与资源明确 |
| AC02 | 可玩闭环 | 授权后完成校准、配置、真实摄像头演奏、暂停、结算、重试；无手柄 |
| AC03 | 手部识别 | 保留集接拍/挥切精确率与召回率均目标 ≥95%，按动作报告 |
| AC04 | Z0 | 真实前后事件召回率 ≥90%、精确率 ≥95%；两方向均测试 |
| AC05 | Z1 | 全样本方向成功率 ≥85%，方向作答准确率 ≥95%、覆盖率 ≥90%，靠近/远离分别报告 |
| AC06 | 干扰与静止 | 各关键负样本至少 50 次，单类误报率 ≤5%；自然非 Z 舞动误报 ≤0.2 次/分钟 |
| AC07 | 回位与刷分 | 100 次动作回位循环，无额外计分；持续晃动不自动连发；Z1 错方向不靠反向修正刷分 |
| AC08 | 无方向公平 | Z0 前后召回率差建议 ≤5 个百分点，不能只对其中一方向有效 |
| AC09 | 配置隔离 | XY/Z0/Z1、模拟/摄像头、规则版本、辅助/正式成绩清楚分离 |
| AC10 | 断续保护 | 失焦、后台、睡眠、摄像头占用、音频暂停等能正确暂停与恢复，无重复加分 |
| AC11 | 性能 | 第14节目标有可复核数据；不达标项列出具体限制，不写成已通过 |
| AC12 | 舞台 | 一套完整科技未来舞台、三配置音符图例、真实动作反馈；低特效仍可读 |
| AC13 | 空间与体验 | 小幅动作可玩，无持续前进/后退导致的被迫出框；至少收集三配置自然性/公平感评价 |
| AC14 | 内容 | 约60秒关卡和32秒段，JSON可编辑、资源本地化、音频与谱面校验通过 |
| AC15 | 测试真实性 | 使用真人摄像头测试，不以键盘模拟、演示视频或模型自预测标签充当识别证据 |

结果按能力报告：

- **XY 验证通过**：基础接拍/挥切和游戏闭环成立，不代表 Z 成立。
- **Z0 验证通过**：无方向纵深脉冲可用，有方向能力仍可未通过。
- **Z1 验证通过**：有方向前后玩法在已测条件成立，同时报告不确定与失败场景；不泛化为任意环境可靠测距。

当前交付必须尝试并记录两档 Z；允许“Z0 通过、Z1 暂未通过”作为诚实的研究结论，但不能把未通过的 Z1 宣称为已实现的正式能力。

## 20｜后续迁移与当前决策

| 决策 | 当前锁定 | 后续扩展触发条件 |
|---|---|---|
| 开发平台 | Mac 浏览器优先 | 可玩与识别验证通过再评估安卓/原生引擎 |
| 摄像头 | 内置单目 RGB 为基准 | 基准可复现后测试 USB/手机镜头 |
| Z | Z0/Z1 同时探索，分档验收 | Z1 通过才进入后续正式方向谱面 |
| 美术 | Starri 参考的科技未来舞台 | 先验证一套，再扩角色和场景 |
| 内容 | 一分钟关卡与32秒实验段 | 三配置有明确体验结论后扩曲库 |
| 分数 | 本地，按配置/版本隔离 | 规则稳定后再引入多人或在线成绩 |

后续安卓迁移可复用动作事件语义、谱面、评分规则、教学与美术资产；摄像头接入、推理性能、权限、时间同步和热稳定性需要重新适配并测试，不能将 Mac 数据直接作为安卓验收。

当前成功标准：玩家能在这台 Mac 上用真实身体动作玩完一段具有科技未来舞台表现的节奏游戏，并能用独立数据判断无方向与有方向 Z 玩法各自是否成立。
