### 1.3 本轮交付与暂缓项

P0交付：单曲约一分钟的两种玩法、入门/标准两档、选曲与曲前准备、30–45秒可跳过教学、计分/Combo/评级、个人最佳、乐句练习、三档动作配置、独立实验室、64秒主曲建议稿与32秒实验对照、科技舞台、故障保护和验证报告。

约一分钟主曲建议采用120BPM、4/4、32小节的64秒结构；替换旧固定60秒倒计时设计，以完整乐句与音乐结束为结算条件。允许使用原创合成音乐，但需有可辨识旋律、鼓组、段落和收尾，不能只交付节拍器。

P1：移动轨迹音符、转轮、原创领舞角色、更丰富的乐句反馈、第二首歌。P2：完整曲库、进阶谱面、多人、装扮经济、在线榜、账号与安卓移植。不得为了首页曲库展示使用不可玩的假歌曲。

## 02｜定位、核心循环与玩家目标

一款“用身体演奏音乐”的体感节奏游戏：玩家看懂即将到拍的音符，用双手挥切、接拍或保持，辅以小幅侧移与可选前后律动，把一首歌连贯地完成。

### 2.1 三层循环

| 层级 | 循环 | 玩家得到的反馈 |
|---|---|---|
| 单次动作，约0.5–2秒 | 预读→准备→到拍动作→判定→恢复 | 时间准确度、对应手的光效、音符被切开或接住 |
| 乐句，4/8拍起步 | 学到动作型→重复→变化→重拍释放→恢复 | 连贯身体动作、连击和随音乐展开的舞台 |
| 单曲与重玩，约1分钟 | 选歌/玩法/难度→演奏→结算→找薄弱乐句→练习或再挑战 | 个人最佳、评级、全连与明确的下一次目标 |

核心反馈先后顺序：节拍清楚→动作有对应→连贯演奏→演出增强→纪录提升。玩家无需先理解Z信号或算法置信度才能玩到第一首歌。

### 2.2 首次与再次游玩

首次：启动/授权→上半身定位与伸展→左右手确认→简短玩法教学→默认挥切·入门·XY→演奏→结算。首次不强制Z校准，不强制完整下肢入镜。启动后完成准备的可用条件应直接显示。

再次：音乐大厅→沿用上次曲目/玩法/难度→短暂人体锁定→4拍倒数→演奏。玩家、镜头和摆放未变时复用校准，质量异常时再引导重校准。

### 2.3 单曲内循环与结束

普通Miss只断连并反馈，不因失误把玩家踢出歌曲。P0没有扣空生命立即失败，也没有失败付费复活。整曲结束再显示完成/达标状态，保证新手能听完、学完。

基础音乐连续播放；成功叠加短促击中反馈，Miss不给成功光效。可选响应乐器层只作为表现，不允许改变主音频时间轴。舞台能量随连续成功变化，连击不额外乘分。

练习、暂停恢复、慢速推理或系统保护使用辅助成绩；正式纪录要求原速、完整、输入有效且无中断完成。

## 03｜玩法、难度与动作配置

### 3.1 两种主玩法

| 玩法 | 读谱 | 主动作 | 节奏体验 | P0组成 |
|---|---|---|---|---|
| 挥切 Slash | 音符从远处沿透视方向接近固定击中面，到面即到拍 | 指定手按箭头方向切过指定区域 | 提前预判、连贯挥臂、重拍释放 | 单手挥切、双手挥切、定点保持、侧移避障、可选Z |
| 接拍 Catch | 目标固定于手部可达平面，收缩环归拢到中心即到拍 | 指定手从目标外进入区域，或接住后保持 | 空间定位、到拍接触、短句呼应 | 单手接拍、双手接拍、定点保持、侧移避障、可选Z |

一首歌开始前选择玩法；歌中不突然切换Slash/Catch读谱。两种玩法可以共用音乐和音乐结构，但谱面独立制作、独立统计成绩。Catch不再使用Slash的透视飞行时间提示；Slash单次挥切以到面为准；定点保持采用独立的固定区域图示，曲前单独教学，不沿用飞行挥切音符的外形。

Slash箭头仅表示手在XY平面的挥动方向；音符从远处飞来仅表示剩余时间，与玩家实际前后移动没有对应关系。

### 3.2 难度

| 难度 | 编排初始目标 | 空间与持续动作 | 状态 |
|---|---|---|---|
| 入门 | Slash约24–36个手部评分单位/分钟，Catch约28–40；同手相邻动作起点通常≥800ms | 以中位四区为主；不强制交叉手；保持不超过2拍；每分钟最多2次侧移避障 | P0 |
| 标准 | Slash约44–60个手部评分单位/分钟，Catch约44–64；同手相邻动作起点通常≥500ms | 加入高低变化、双手呼应和2–4拍保持；每分钟最多4次侧移避障 | P0 |
| 进阶 | 后续根据识别性能和体力测试编排，不先承诺极限密度 | 轨迹/转轮等通过验收后才加入 | P2 |

密度是编排起点，需转换为整曲整数并按可达性校验；双手音符按一枚评分单位计算，身体/Z单位另计。密度上限不覆盖动作冲突规则：同手保持期间不得再安排该手挥切或接拍，不在同一区域叠加不可分辨事件。

P0两档均可直接选择，入门A及以上只给“推荐挑战标准”，不强制解锁阻断测试。

### 3.3 动作配置与身体可见范围

- **XY原地**：默认配置，肩部与双腕可靠即可进入；侧移避障使用肩中心/躯干上部横移，不要求脚步或髋部参与评分。能转动手部光标不等于Z已可用。
- **Z0前后律动**：在主玩法乐句中加入任意方向整体纵深脉冲，需双肩双髋及Z0校准通过。
- **Z1方向律动·实验**：要求明确靠近/远离，需全身核心关节及Z1校准通过。方向不确定保持拒判，不按谱面预期猜测。

“全身校准”在本轮指双肩双髋可靠；不要求膝踝必须入镜。动作空间不足可主动选择XY。Z0/Z1不是“更高难度”的同义词，难度和能力不得相互自动替换。

### 3.4 主入口与辅助入口

主入口：音乐大厅、选曲、玩法与难度、开始；设置入口：定位/同步/摄像头/显示；辅助入口：乐句练习、动作实验室。

动作实验室继续保留骨架、模型信息、Z0/Z1、真值试验和报告导出；玩家不必经过实验室才能选歌，退出实验室不改变采集生命周期。

### 3.5 本轮可玩组合矩阵

| 内容 | 玩法 | 难度 | 配置 | 份数 |
|---|---|---|---|---:|
| 64秒主曲核心 | Slash、Catch | 入门、标准 | XY | 4 |
| 64秒主曲Z扩展 | Slash、Catch | 入门 | Z0、Z1 | 4 |
| 32秒实验控制段 | Slash | 入门 | XY、Z0、Z1及Z1方向反序 | 4 |

共12份可加载谱面，允许由同一基础谱面及显式替换段生成；每份需独立ID/版本并校验。标准难度Z0/Z1本轮不交付，界面只展示真实可玩组合。玩家选择不可用组合时说明原因，不悄悄改成另一份谱面。

## 04｜Mac 运行环境与设备要求

### 4.1 默认运行方式

在 Mac 启动本地服务，用桌面浏览器访问 `localhost`。浏览器请求摄像头权限，在本机执行姿态识别、动作分析、音频和图形渲染，不上传原始视频。

本轮优先验证当前 Mac 上的 Chrome 稳定版本，记录实际浏览器、系统和模型版本；Safari 的兼容性作为后续检查项，不将未经测试的浏览器写入支持名单。

现有原型使用TypeScript、Vite、Web Audio、Three.js与MediaPipe；后续沿用并锁定依赖。当前人体模型为Google MediaPipe Pose Landmarker Lite（官方float16/1模型包），SDK为`@mediapipe/tasks-vision 0.10.32`，CPU/WASM、独立Worker、单人33个姿态关键点。Z由项目时序算法估计，不是模型直接输出整体绝对距离。无需安卓模拟器、手机或游戏机。

摄像头页面须运行于 localhost 或 HTTPS；权限拒绝、摄像头被其他应用占用、模型资源加载失败均有恢复路径。浏览器摄像头权限和音频启动按其用户交互要求实现，不能假定打开页面就能自动播放音乐。[摄像头 API 说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

### 4.2 摆放与显示

- Mac 固定在稳定平面，开局后不调整机身和屏幕角度。
- 玩家保持正面，确保抬手、侧摆和小步前后移动时仍在取景范围内。
- 不启用会改变有效取景尺度的人物自动跟随、自动变焦或动态裁切；若不能确认关闭，对 Z 测试标注限制。
- 默认 Mac 屏幕显示，可选有线外接电视；外接后单独校准视听链路。
- 原型不默认使用无线投屏、蓝牙音频或手机连续互通相机作为基准输入/输出，避免引入额外变量。
- 不强制固定站距；约 2–3 米仅是试摆起点，以玩家完整动作入框和清晰可读为准。

### 4.3 操作边界

第一次启动、浏览器授权和调试可用鼠标键盘。完成启动后，选配置、开始、暂停、结算和重试支持裸手闭环；同时保留 Esc 暂停与点击操作，便于开发测试。

键盘模拟输入必须明显标为“模拟输入”，只能检验谱面和反馈，不能作为真实摄像头识别通过的证据。

## 05｜分级定位与三档Z校准

| 步骤 | 玩家动作 | 输出与成功条件 | 失败处理 |
|---|---|---|---|
| 摄像头准备 | 选择镜头并授权 | 摄像头与模型正常，实际帧尺寸可见 | 重试、换镜头、查看权限说明 |
| 人体锁定 | 正面站稳约 2 秒 | 主玩家、关节置信度、原始画面尺度 | 提示补光/调整站位 |
| 舒适范围 | 抬手、左右伸展、轻侧摆 | 手部触达范围及静态噪声 | 重校准，缩小目标范围 |
| 左右确认 | 跟随示范举左手、右手 | 镜像与解剖学左右一致 | 修正显示映射后复验 |
| Z0 校准 | 小幅前后动 3 次，每次停稳 | 能稳定识别运动事件且静止不误触发 | 保留 XY，显示 Z0 未通过 |
| Z1 校准 | 在提示下分别靠近/远离各 3–5 次 | 得到两方向分布、置信度、混淆与拒判情况 | Z0 可继续，Z1 标注待改进 |
| 音画/动作同步 | 跟随 8–12 个拍点 | 当前设备链路综合偏差 | 重试或使用临时偏移并标注 |

Z1 的校准真值来自测试指令与人工核验；不能把系统自己的预测当真值。校准通过只证明当前人的当前场景可进入测试，不等于多人多环境准确率已达标。

保存两类独立数据：用于手部映射的身体相对坐标，以及用于整体纵深分析的原始图像尺度与变化历史。不能先把每帧人体统一缩放，再用已归一化尺寸判断前后。

更换玩家、镜头、机身位置或裁切后重校准。Z1 单次试验内冻结参考基线，防止前进被自动重设为新原点；重新设定原点只能在明确的重置阶段执行并记录。

### 5.1 分级进入而非全流程阻断

可靠双肩/双腕和舒适范围完成后可选“仅上半身，开始XY”；髋部不足不妨碍该入口。界面逐项显示关节是否在画面内、置信度是否合格，预览与校准使用同一可靠性标准，不再统一提示“肩宽不足”。当前校准阈值起点为65%，参数修改需版本化。

需要Z时另做双肩双髋基线与Z校准，膝踝不是门槛。先完成XY不算Z失败，也不应强迫玩家在首局前走完整方向实验。Z初次使用或站位变化后重校准。

## 06｜音符、身体动作与判定规则

### 6.1 动作字典

| ID | 单位 | 玩家动作 | 使用位置 | 优先级 |
|---|---|---|---|---|
| A01 | 接拍 Catch | 指定手在目标拍进入指定区域 | Catch | P0 |
| A02 | 挥切 Slash | 指定手按箭头方向切过区域 | Slash | P0 |

### 6.2 公共空间映射

以身体舒适伸展范围映射到舞台归一化XY，左右镜像遵循玩家自己的左/右手。身体整体侧移不把手部目标瞬间平移，避免避障改变手感；开局冻结本局映射，必要重校准需暂停。目标分左/右高、中、低六个布局区，不是六个键盘按键；区内位置仍需命中。

左右手用颜色+形状+L/R图示区分；不以双手互换完成指定手音符。上半身模式的目标不超出已校准触达范围。

### 6.3 接拍

目标出现后先给预读：入门提前1.5–2秒，标准至少1.2秒；收缩环到中心为目标时间。进入过早不能锁定等待得分，需离开并在有效窗口内重新进入。

手腕从目标外进入，连续确认初始60–100ms，计时取首次进入的采集时间。刚好生成在已停留手腕下的音符不能自动得分。完成后撤出到外侧迟滞边界，才允许下一枚同区接拍；边缘抖动不得重复触发。

### 6.4 挥切

箭头指示XY切向，连续有效手腕轨迹穿过目标、幅度与方向均合格才命中。初始方向容差±45°；最小幅度基于校准肩宽/舒适范围，不用屏幕像素硬编码。建议首轮试调为校准肩宽约15%，需真人验证，不能靠手部静止覆盖判挥切。

入门优先上/下/左右直切，标准再加入斜切；不在一次连续挥动路径上塞入多枚音符来自动串分。一次动作事件最多消费一枚单位，明确编排的双手单位各消费一条手事件。长采样缺口后的连线不是有效轨迹，静止与回程不自动生效。

### 6.5 双手

一枚包含左右两个子目标，两手开始时间差初始≤120ms，各自满足区域/方向/时间窗。整枚评价取较低档，Combo只加1；只命中一手可按该手评价获得整枚权重一半的分数，整枚仍记Miss且断连。配对同时预读，不用一个手部事件消费两只手。

### 6.6 定点保持

持续1–4拍，指定手先在首拍有效接入，随后保持到尾拍。展示首环、持续能量和尾环；起拍接入合格且尾拍仍在区域时，按有效覆盖率≥90%/75%/50%给Perfect/Great/Good，再与起拍时间评价取较低档；覆盖低于50%、起拍不合格或尾拍提前离开记Miss。尾拍只要求保持在区内，不要求刻意松手，也不再采集一个“释放动作时间”；缺失可靠观测按保护处理。

同一保持单位只计分与增连一次，尾部最终结算；头部给临时视觉反馈不先增加最终Combo。短暂边缘抖动可宽限约100ms，宽限仅处理有效观测下的边缘退出，不把没有可靠观测的时间填成成功；输入失效按系统保护处理。统计按时间覆盖，不按帧数平均；一枚保持权重1，时长不暗中抬高分值。

### 6.7 侧移避障

显示左侧或右侧障碍墙，以及明确的“向左/向右”安全区。使用肩中心横移，正面可见且双肩可靠；不把单纯转身或一侧肩丢失当成功。初始安全区位移门槛为校准肩宽约20%–30%，需按舒适范围验证。

障碍提前至少2秒预告；在占用区间开始前最后500ms内，从中心准备区进入指定安全区，并在0.5–1秒的障碍区间内保持；过早停在安全区不自动得分，需回中心重新触发。到拍首点使用身体时间窗，覆盖率≥90%/75%/50%与时间评价取较低档，低于50%或没有合法进入记Miss。边缘迟滞与Hold相同。

每道障碍权重1，结束结算一次；非评分恢复段至少1秒，回中心不加分。失败表现为护盾闪烁，不强制结束歌曲。避障开始前500ms、结束后1秒不安排强制手部/Z动作；P0不要求身体侧移同时精准击手部音符。左右避障交替只用于可达性，不让算法从预期方向反推输入。

### 6.8 《舞力全开》参考：示范、预告与连贯舞句

参考分工明确为：Starri提供挥切/接拍玩法骨架，《舞力全开》提供看示范跟动作和整曲舞蹈演出的体验方向，《节奏大师》提供清晰读谱与逐曲挑战。三者融合在同一音乐时间轴，不额外强制玩家同时完成“打音符”和“模仿舞者”的两套任务。

P0使用原创简化动作示意/轮廓，曲前展示左右手、接拍/挥切、保持与侧移；演奏中在乐句开始前1–2拍给小型下一动作预告，Z/避障仍按各自至少2秒的提前量。示范手别、动作方向与下一枚音符一致，按玩家镜像理解制作；不能让示范要求左手、音符却要求右手。动作按4/8拍衔接，重复后变化，自然回位。

本作当前以音符、保持、避障和Z事件评分，不要求玩家逐关节复制完整舞姿。额外摆动不加分，未列为评分要求的腿部、表情和身体风格不扣分；不得显示未经实现的“舞姿相似度”。

P1原创领舞角色负责与同一谱面同步的预设编舞和教学，置于不遮读谱的位置；音符与角色冲突时必须修正编排，不能让玩家猜应该跟谁。后续若增加整段编舞匹配，应另立玩法与算法需求、数据/容差与真人验收，不直接混入现有正式评分。

## 07｜Z 识别：共同原则与两档能力

### 7.1 可实现性与限制

固定单目摄像头可以利用同一玩家在连续画面中的表观尺度、身体关键点和运动趋势，估计是否发生整体前后移动，进一步尝试区分靠近或远离。这里是工程方案和待验证假设，不承诺任意姿态、任意光照均可靠。

在近似针孔成像、同一人保持近似正面且姿态变化较小的条件下，图像尺度与距离近似成反比。若尺度从 s0 变为 s，可用 `相对距离比例 ≈ s0/s` 构建粗略特征；该值不等于厘米，不可在显著转身、屈膝或动态裁切时直接使用。

MediaPipe 的关节深度与世界关节坐标以髋部中点为原点。因此，要另行分析整个人相对摄像头的移动，不能直接用髋部关节 z 或“手比髋部靠前”替代整体平移。[坐标定义](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

### 7.2 共同处理管线

原始图像坐标 → 多关节置信度检查 → 正面/弯腰/屈膝等姿态质量检查 → 多部位尺度与运动趋势 → 时间滤波与迟滞 → 候选事件 → 持续性确认 → Z0/Z1 输出。

可融合肩宽、髋宽、躯干相关距离和人体局部光流，但不以单一人体框或单一肩宽下结论。模型裁切 ROI 变化、摄像头移动和自动取景均需排查；本轮无法可靠检测的情况通过固定摆放、关闭功能和测试记录控制，不能声称系统能自动识别所有相机扰动。

真实靠近/远离为正样本；静止、挥臂、扩胸、弯腰、侧转、横移、屈膝、手前伸、镜头变化与其他人入镜为负样本或必须拒判的条件。

### 7.3 Z0：无方向空间脉冲

- 输出 `DepthPulse`：只表达发生了合格整体前后移动，不带方向条件。
- 玩家用语：“身体前后轻轻动一下，向前、向后都可以。”
- 使用对称双环/身体图标，成功播放固定能量扩散或空间展开。
- Z0 不依赖 Z1 先得出方向：方向证据不足、但整体纵深证据足够时仍可能输出 Z0；整体证据也不足则拒判。
- 只知道无方向运动时不能证明回到物理原点；回位是引导，停稳不等于回原点。

### 7.4 Z1：有方向前后律动实验

- 输出 `DepthStep`，方向仅可为 `toward_camera` 或 `away_from_camera`；证据不足输出诊断状态 `uncertain`，不生成可评分方向事件。
- 明确玩家语义：“靠近摄像头/屏幕一步”“远离摄像头/屏幕一步”。当前默认屏幕与镜头同侧；改变摆放时先改教学，不能沿用含混的游戏世界前后。
- 靠近拍用向中心聚合的门形符号与“靠近”文字，远离拍用向外退开的门形符号与“远离”文字。不能只靠透视大小和颜色区别。
- 只有整体移动、方向和置信度均合格才消费音符；不要从谱面预期方向反推识别结果。
- 动作方向可被估计，不代表能准确获得当前位置。首版不做连续自由 Z 移动控制，也不做精确距离门槛。
- 相对站位指标可用于“接近初始范围”的辅助提示，须标注估计；它不能作为已经证明回到精确物理原点的依据。

### 7.5 状态机与回位

`未就绪 → 稳定约300ms → 可触发 → 候选 → 持续确认约100–180ms → 输出一次 → 恢复锁定 → 再次稳定`

共同要求：进入阈值高于退出阈值；动作事件唯一 ID；确认后回溯首次满足条件的采集时间；初始恢复锁定至少约 800ms，且谱面恢复空段未结束时不重新计分；持续摇摆和持续走动不能定时自动连发。

游戏同一动作最多消费一个事件。测试场允许显示动作和回程两个物理运动片段，但需要标注所属试验和阶段；游戏回位阶段的运动不得产生额外得分。

Z1 错方向后仍进入本次试验恢复阶段，不能立刻反向修正刷同一枚音符。下一次动作需等待稳定和新提示。

### 7.6 Z 谱面约束

1. 初版两个 Z 计分点至少相隔 3 秒，编辑器按毫秒检查。
2. 普通 Z 提示至少提前 2 秒，新手建议 3 秒；方向提示必须足够早让玩家理解。
3. 初始在 Z 判定前 500ms、后至少 1000ms 清空强制手部音符、侧移避障和定点保持；实际回位更慢则延长空段。
4. Z1 从舒适中心发起小步动作，在非计分空段回位；不连续要求多次同向移动，不允许累计后退。
5. 单段 Z 只在乐句重拍使用，建议占评分单位约 5%–10%；32 秒控制段可为实验目的单独标记密度。
6. 不提高步幅来强行弥补不稳定识别。若安全的小幅动作不能识别，记录失败并调整方案。

### 7.7 降级与不确定

曲前校准不通过：给出问题 → 重试或主动选低一级配置。Z1 可以切 Z0，Z0 可以切 XY，切换后加载独立谱面。

演奏中不静默切换配置。出现不确定事件时先显示短提示，当前音符进入系统保护；关键关节持续低质量约300ms时暂停。单纯帧率偏慢遵循第14节，不等同于低质量或断流。重校准后继续为辅助成绩，或者从头重开原配置。

实验评估必须保留全部不确定、未输出和错方向样本，不能只报告系统愿意作答的样本准确率。

## 08｜歌曲结构、谱面与舞句编排

### 8.1 从固定时长试玩改为完整音乐单局

选定一首原创/已授权音乐，P0建议120BPM、4/4、32小节、64秒。倒数在主曲前，结算在音乐自然结束且所有单位完成最终判定后。计时显示进度，不以独立计时器抢先切断歌曲。32秒内容作为实验对照/练习素材，主流程不混入“测试段”。

| 段落 | 时间 | 编排目标 | 表现 |
|---|---|---|---|
| Intro，1–4小节 | 0–8秒 | 稀疏左右动作，建立到拍规则 | 简洁舞台启动 |
| A，5–12小节 | 8–24秒 | 建立4/8拍动作型并重复；一次特殊节点 | 加入左右光轨 |
| B，13–20小节 | 24–40秒 | 位置/方向变化，一次保持与特殊节点 | 舞台层次增加 |
| A′，21–28小节 | 40–56秒 | 回归熟悉动作型，少量变化；一次特殊节点 | 重拍演出增强 |
| Outro，29–32小节 | 56–64秒 | 一次特殊节点、回位、双手收束、留白 | 明确结束与余响 |

两玩法共用段落标记，手部谱面分别设计：Slash依次挥臂形成连续轨迹，Catch用左右空间呼应和保持形成身体展开，不能只是同一组点换图标。

### 8.2 三配置的可比性

在每个玩法/难度内部，XY/Z0/Z1保持同一音频、共同手部事件和特殊时点。入门主曲初始安排18、30、46、58秒共4个特殊评分单位：XY为双手接拍/双手挥切（由玩法决定），Z0为任意方向脉冲，Z1为指定方向。4个特殊单位建议占总权重约5%–10%，最终需按实际谱面计数核对。

每个特殊单位从提前3秒预告开始不再新开可能冲突的保持；判定前500ms、后至少1秒为强制动作净空，并给2–3秒非评分回位引导，直到已稳定才继续需要精细控制的动作。XY也保留同样空段，避免Z版因为留白而更易获得其他分数。

Z1方向数量均衡，测试使用顺序变化与反序变体；不连续多次同方向累积位移。主曲的恢复空段必须在文件中显式标记，不依赖口头约定。

### 8.3 身体可达性与音乐性

每个4/8拍短句遵循“准备→动作→变化→恢复”，同手大范围高低跳转、反向挥切和保持释放需留出恢复时间。身体避障与Z互斥；不在Z前后塞入大幅扩胸/交叉手来制造尺度干扰。没有到拍事件的乐句可以自由舞动，不能靠自由摆动生成谱外分数。

难度主要来自有规律的动作型变化、双手协同与读谱组织，而不是盲目提高音符速度或把窗口压到模型采样间隔以下。试玩时检查动作自然性和读谱理解，不能仅靠JSON合法就认为谱面合格。

### 8.4 32秒控制段

保留v1.1的120BPM、16小节、32秒控制段，限定Slash·入门；普通手部改为挥切/双手挥切，10秒与22秒为特殊时点：XY双手挥切、Z0任意纵深、Z1靠近/远离。另保留Z1反序版本。

四份对照段共用音频、常规手部、预告与恢复空段，只替换特殊动作。此段不承担双玩法留存或正式曲目排行，不把少量Z样本当作方向准确率验证。

## 09｜评分、连击、成绩资格与时间轴

### 9.1 时间与动作合格双条件

动作类型、指定手、区域和方向先合格，再按时间误差评价。不能只检测“这一刻有动作”就给分。

| 评价 | 手部单次/保持起拍 | 身体进入/Z事件 | 系数 |
|---|---:|---:|---:|
| Perfect | ≤90ms | ≤160ms | 1.00 |
| Great | >90–150ms | >160–260ms | 0.80 |
| Good | >150–230ms | >260–380ms | 0.50 |
| Miss | 超窗/动作不合格 | 超窗/动作不合格 | 0 |

以上为本作初始窗口，不是Starri或《节奏大师》的参数。Hold/Dodge另结合覆盖率并取较低档，详见第06节。Z1方向明确但相反为Wrong Direction，按Miss结算；方向不确定/关键输入失效为System Protected，不补成功，也不当作已知错方向。

### 9.2 得分、准确率与完成标记

`总分 = round(1,000,000 × Σ(单位权重 × 实得系数) / Σ(谱面全部单位权重))`

`准确率 = 100% × Σ(单位权重 × 实得系数) / Σ(谱面全部单位权重)`，显示两位小数。双手单位的部分分按第06节；Hold/Dodge均权重1且只结算一次。默认全部单位权重1，无隐式类型倍率。正式与辅助都保留完整分母，保护单位实得0并单列，不能用删除分母制造高准确率。

- Perfect/Great：Combo+1；Good：有分、断连；Miss：断连。
- System Protected：不给分、不加连，并将本局转辅助；从保护点结束当前连击段，后续重新统计，避免跨缺口制造全连。
- Full Combo（全连）：整曲所有单位均为Perfect/Great，且成绩正式；双手只中一手不算。All Perfect：所有单位Perfect且正式。
- 评级：S≥95%、A≥85%、B≥70%、C≥50%、D<50%，使用未四舍五入准确率判断边界。
- 播放到结尾为“完成”；正式且≥70%为“达标”。完整播放但低于70%显示“已完成，继续练习”；辅助显示“练习完成”，不标正式达标或全连。

不使用连击乘分、角色能力加分或舞台能量倍率。辅助局不能覆盖正式最佳，练习提示也不能冒充新纪录。

### 9.3 纪录隔离与公平性

纪录键至少包含：歌曲/音频版本、谱面ID/版本、玩法、难度、XY/Z0/Z1、上半身/双肩双髋校准、输入类型、判定规则版本。辅助局单列最近结果；模拟输入和真人摄像头分开。

同一纪录键只按正式总分更新最佳，同分优先较少Good/Miss、再较大最大连击；完全相同保留原纪录。不同玩法/配置的分数不直接做“更强玩家”比较。调参修改判定规则后另开版本，不覆盖旧比较基线。

### 9.4 音频主时钟与缓冲

以Web Audio为唯一谱面主时钟。分别记录帧采集/视频时间、推理开始/结束、动作候选开始/确认和音频映射。判分使用候选发生时间，不能使用Worker回包到达时间，不能把模型推理耗时全部算成玩家晚拍。

手部/身体单位采用相应有界最终结算缓冲，初始手部约200ms、Z约350ms，需实测调整；到拍可先有临时反馈，确认后才写最终评价。缓冲不是额外玩家窗口，超缓冲技术失效按保护处理。Hold/Dodge结束后同样等待必要结果再结算。

暂停、后台、系统睡眠或音频上下文恢复后检查时钟映射。综合同步偏移只补偿一次；软件推理时间不是动作到画面的端到端测量。

### 9.5 去重与暂停恢复

同类型、同手、同区域有效候选优先匹配时间差最小单位，同差值取较早单位；物理事件与单位一对一，Pair通过配对关系消费两只手各一条事件。保持/避障按生命周期结算，不按每帧重复计分。

暂停同时冻结音频、谱面与持续单位计时，清空未消费的旧轨迹。继续前锁定人体并4拍倒数，从安全乐句边界恢复；若回放已判片段，先撤销该片段原得分/判定/Combo贡献再重算。局资格保持辅助，不用暂停反复尝试刷正式纪录。

## 10｜页面与裸手交互

### 10.1 信息架构

| 页面 | 必须内容 | 主要去向 |
|---|---|---|
| 音乐大厅/选曲 | 真实可玩曲卡、曲名/时长/BPM、上次选择、对应玩法最佳 | 曲前准备；次要入口为练习、设置、实验室 |
| 曲前准备 | Slash/Catch、入门/标准、XY/Z0/Z1、输入与能力状态、该组合动作图例 | 开始、教学、必要校准 |
| 定位与教学 | 当前所需关节、镜像左右、舒适范围、动作示范、同步 | 完成后返回原曲目选择，不丢失配置 |
| 演奏 | 玩法对应读谱、双手反馈、分数/Combo、歌曲进度、小型输入状态 | 音乐结束→结算；暂停→恢复面板 |
| 暂停 | 明确原因、继续、重来、返回选曲 | 继续前锁人/倒数；更改配置必须重开 |
| 结算 | 成绩/资格、最佳差值、判定分布、薄弱乐句、下一步建议 | 同配置重试、练这一段、返回选曲/推荐难度 |
| 乐句练习 | 4/8小节段落选择、0.75/1.0速度、循环、难点类型 | 进入练习或回原曲目 |
| 设置 | 摄像头开关、显示预览、音量、效果、同步、数据清理 | 返回上次页面 |
| 动作实验室 | 骨架/模型/帧率、Z诊断、人工真值试验与报告 | 主动返回大厅；不是必经页 |

P0仅一首歌时仍做真实曲卡和双玩法/双难度，不用大量锁定假曲装点曲库。默认选中Slash·入门·XY，上次选择可覆盖默认。

### 10.2 手部菜单光标

菜单使用一只主控手；教学时确认，默认右手，左手可切换。另一只手仍可显示为次光标，但不能同时触发菜单。主手丢失时提示恢复，不无提示地把控制权交给另一人/另一只手。

指向按钮稳定停留约1秒，显示进度，移出取消；无新可靠姿态时立即停止累积。菜单停留与音乐判分是独立机制，菜单停留不得用于演奏接拍。

页面切换、弹层出现、暂停和结算之后，必须先看到主控手离开所有操作热区，再允许新的1秒停留；已停在按钮位置不能连锁开始、返回或重开。识别不足时保留鼠标键盘恢复。

演奏关闭菜单停留逻辑，只保留游戏手部光标。主动暂停使用双手举过头顶窄区保持约1.5秒，谱面不使用该姿势长保持；与正常高位音符分开验收。Esc/点击暂停保留。

### 10.3 跨页面连续输入

摄像头/推理属于整次网页会话，独立于实验室、首页、舞台等页面组件。实验室仅展示预览；隐藏预览或切页不停止采集，模型不重载，轨迹状态在需要时清空但不销毁摄像头源。

页面切换后使用新到姿态驱动光标，禁止复用过期手位置累积停留。舞台准备要确认近期视频帧和模型结果均有效，再启动音频倒数。只有明确关闭摄像头或退出整个网页才释放流与Worker。

## 11｜科技未来感美术规范

### 11.1 视觉方向：未来光轨竞技舞台

明确采用用户指定的 Starri 科技未来感参考：深色空间、远近透视、悬浮几何音符、发光切线、能量粒子、金属/半透明舞台装置和风格化表演角色。

“未来感”落在可制作的元素上：远处舞台核心、两侧透视光轨、稳定击中面、手部短光刃、Z 能量门、连击激活的舞台层。不是把画面变成密集仪表盘。

用户选定的科幻方向优先；采用青蓝/紫色空间光和高饱和特效是有意参考，不为套用通用商务界面规范而移除。高亮集中在音符、动作与成功瞬间，读谱平面保持安静。

### 11.2 色彩、形状与材质建议

| 角色 | 建议色值 | 用法 |
|---|---|---|
| 深空底色 | #080D1C | 主舞台背景，低亮度 |
| 空间辅光 | #6556D9 | 远处装置、切景和环境光，不盖住目标 |
| 左手主色 | #50D9F5 | 圆芯/左标记与短光刃 |
| 右手主色 | #FF85B9 | 菱形/右标记与短光刃 |
| Z0 | #FFE39B | 对称双环，能量扩散 |
| Z1 靠近 | #A5F4D1 | 向内门形+“靠近” |
| Z1 远离 | #FFC18B | 向外门形+“远离” |
| 正文/Perfect | #F4F7FF | 清晰实体文字，不做发光细字 |

手别与方向均用颜色+形状+文字重复编码，不能只靠颜色。左右手和 Z 的形状需在低特效、灰度和静止图例里仍能区分。

舞台可用程序化 WebGL 几何实现有意义的光轨、装置和能量环；这些就是游戏场景资产，不使用无关图片填充。原型先完成一套原创舞台，不复刻 Starri 角色、界面或资源。

### 11.3 布局与动效

- 16:9 为关卡设计基准，Mac 非 16:9 窗口居中适配；不拉伸相机输入，不因窗口变化破坏手部映射。
- 中央约 65%–75% 是主要读谱区，左/右高、中、低六区；初始难度以中部四区为主。
- Slash音符沿透视方向接近固定击中面，视觉Z表示时间；Catch目标固定于手部可达平面，以收缩环表示到拍。两种玩法的时间提示不能混用，都不冒充玩家真实距离。
- 普通音符提前约 1.5–2 秒可读；Z 提示固定于主视线附近，至少提前 2 秒；不被角色挡住。
- 背景光轨可以随音乐变化，击中面和输入映射不能随装饰相机漂移。
- 手部短尾迹即时跟随；挥切 120–180ms 碎片反馈；Z0 300–500ms 扩散；Z1 用已确认方向触发靠近聚合/远离释放的预设反馈。
- 不把角色连续前后走位当精确捕捉演示；Z1 初版只做离散方向事件反馈。
- Combo 放在上方外围，判定文字不得覆盖下一枚目标；背景切景不在高密度段发生。
- 标准版有完整科技舞台，低特效版去掉屏震、强粒子和大范围闪光，保留音符与方向图示；拒绝频闪作为必要提示。

### 11.4 原型资产清单

P0：一套未来舞台、Slash/Catch两套到拍图形、双手/定点保持/侧移障碍/Z0/靠近/远离图示、左右光刃、判定与保护反馈、动作教学示意、曲卡/难度/准备/结算/乐句练习界面。

P1：一个原创风格化角色或简化运动化身、上身受约束跟随、脚部预设动画。角色系统不阻塞 P0；没有正式角色时用明确设计的身体能量轮廓，不用灰色占位框。

字体使用已确认许可的清晰字体，显示文字和数字分层；Mac 窗口和有线电视两种观看距离都需验收。导航正文以对比度 ≥4.5:1 为目标，重要图形边界 ≥3:1。按钮具有普通、指向、停留、触发、不可用、加载和错误状态。

## 12｜歌曲、谱面与数据配置

### 12.1 内容最小集

一首建议64秒的自有/合成/已授权主曲、一段32秒控制段，具体组合按第3.5节共12份谱面交付。另有不计分教学示例与乐句练习切片；练习复用正式谱面范围，不为每个片段复制一套难以维护的数据。

音频包含可辨识段落和自然收尾；反馈音、音乐音量分离。主曲与两个玩法共同使用同一音频时间基准，视觉玩法改变不替换目标时间。

### 12.2 配置字段

| 对象 | 必需字段 |
|---|---|
| 歌曲 | ID/版本、名称、音频/校验、时长、BPM/变速表、拍号、起拍偏移、来源许可、段落标记 |
| 谱面 | ID/版本、songId、playStyle Slash/Catch、difficulty、motionProfile XY/Z0/Z1、ruleVersion、requiredCapabilities、events、restZones、stageTrack |
| 单次单位 | 唯一ID、targetTime、type、hand、归一化XY/半径、方向/配对ID、权重、previewLead |
| 持续单位 | startTime/endTime、合法区域、指定手或身体安全区、覆盖阈值、起止判定与恢复区 |
| Z单位 | DepthPulse无方向；DepthStep明确toward_camera/away_from_camera；预告、恢复区和实验标识 |
| 乐句 | phraseId、起止小节/时间、标题、动作型、对应练习范围 |
| 运行结果 | 谱面与规则标识、输入/校准范围、资格与原因、单位判定、分乐句统计、性能摘要 |

菜单能力限制从requiredCapabilities生成；不可用组合不能加载错误谱面。旧chart的单一mode字段需明确映射到motionProfile，新增playStyle/difficulty；不把旧混合谱面自动标为已验收Slash或Catch。

### 12.3 编排与校验

P0使用可编辑JSON、预览与校验脚本，不要求完整可视化编辑器。校验包含：文件/枚举/唯一ID、音频范围、BPM和乐句边界、时长首尾、手别、Pair完整性、保持期间同手冲突、侧移净空、Z间隔/预告/恢复、可达范围、玩法允许类型、矩阵是否齐全、各配置共同段一致性。

与JSON合法性分开安排真人可读性/动作负荷审核；自动校验不证明舞段好玩。

### 12.4 离线与资源

运行依赖、模型、音频、字体和场景资源准备到本地，本地服务启动后不依赖CDN，可断公网玩完整曲。离线不等于直接双击file页面。商业音乐与参考游戏资源不随本原型打包。

## 13｜浏览器技术架构与数据契约

### 13.1 模块边界

`摄像头 → 视频帧/时间戳 → Worker 姿态推理 → 动作特征与 Z0/Z1 → 音频时间映射 → 谱面匹配 → 分数/光效 → 本地结果`

主线程维护页面、Web Audio 主时间轴和 Three.js 舞台；Worker 处理模型推理与较重特征分析。帧传递采用有界队列，处理不过来时丢弃过时待处理帧并记录，不堆积无限延迟；持续性能偏慢标为辅助并提示，真正输入失效才暂停，详见第14节。

视频只采集一次，测试场预览和推理共享同源输入；不为每个模式重复开启多个摄像头流。输入、特征、事件、判分、渲染分层，未来安卓可替换采集和推理适配层，保留谱面与规则语义。

### 13.2 数据契约

| 数据 | 必需字段 |
|---|---|
| 姿态帧 | 会话/帧 ID、视频时间、单调时钟映射、关节/可见性、原始尺寸、跟踪质量 |
| Z 特征 | 多部位尺度、稳定基线、变化趋势、姿态质量、排除/拒判原因 |
| Z0 事件 | 唯一 ID、`DepthPulse`、候选开始/确认时间、无符号强度、置信度、试验阶段 |
| Z1 事件 | 唯一 ID、`DepthStep`、相同时间字段、方向、方向置信度、试验 ID；不确定另记状态 |
| 诊断状态 | `stable/moving/uncertain/unavailable`、原因、事件/会话关联 |
| 判分 | 音符/事件 ID、配置/规则版本、最终评价、时间误差、错方向或保护原因 |
| 实验结果 | 人物匿名 ID、真实动作标签、预测/未输出、阶段、模式/光照/衣着、性能统计 |

同一物理动作可以被算法对照地评估 Z0 和 Z1，但游戏只订阅当前配置的一条计分路径，不能对两个输出重复加分。两档的成功率分别统计，不强行认为 Z1 正确就代表全部 Z0 测试已通过。

### 13.3 测试场显示

必须能看见：原始画面与骨架、手轨迹、尺度趋势、基线、当前检测方向/不确定、置信度、恢复锁定、拒判理由、采集/推理/渲染帧率。

测试参数可以修改，但每次参数变化产生配置版本并写入结果。人工标签来自独立指令与观察；调参集与保留验证集不能混用。

### 13.4 会话输入与玩法运行状态

采集视频源常驻在页面内容替换区之外，预览独立挂载同一流；页面路由不得销毁采集源或重复启动Worker。分别追踪摄像头新帧、推理结果、姿态质量，不用一个“最后收到姿态”时间把所有故障都解释为镜头故障。

模式运行状态包括preparing/countdown/playing/paused/finishing/results，菜单另有“等待离开热区/可停留”状态；成绩资格一旦降为辅助，本局不能自动升回正式。音乐自然结束后进入finishing，等待有界结果结算再展示results。

诊断/判分/结果增加playStyle、difficulty、motionProfile、phraseId、持续单位覆盖率、资格变更原因；实验室输出保留模型名称/SDK与推理后端。

## 14｜性能、兼容性与故障处理

### 14.1 初始性能目标

| 指标 | 当前 Mac 原型目标 |
|---|---|
| 相机帧率 | 请求并验证约 30fps，记录实际帧率 |
| 姿态输出 | 常态目标≥25次/秒；低于20次/秒持续约2秒提示、降特效、转辅助练习并继续，不宣称正式性能通过 |
| 主舞台渲染 | 目标 60fps；低特效档至少稳定 30fps |
| 手部处理链 | 可测帧时间到事件可用 P95 ≤120ms |
| 动作到可见反馈 | 本机内屏 P95 ≤150ms，外部参考测量；Z 确认时延单报 |
| 校准后时间残差 | 中位绝对误差目标 ≤40ms，P95 ≤80ms；统一测量定义 |
| 连续运行 | 20 分钟循环无崩溃、失控内存增长或持续识别降速 |
| 离线 | 本地资源准备后断公网完整跑完三种配置 |

Web 时间戳不一定暴露完整传感器曝光时间；软件内部处理耗时不能代替端到端延迟。报告需区分可观测软件时间与外部测量结果，未测项明确标注。

先减少背景粒子、光晕和角色复杂度，再调整识别频率或输入规格；更改推理设置后重新验证精度，不静默放宽判分继续比较成绩。

### 14.2 必须处理的异常

摄像头权限拒绝/被占用、设备移除、模型或音频加载失败、暗光/遮挡/出框、其他人入镜、浏览器标签页隐藏、窗口失焦、系统睡眠、音频上下文挂起、输出设备切换、性能不足、存档失败。

区分三类异常：①仍有新帧/结果但推理慢：不报断流，降特效、辅助练习且不改判分窗；②摄像头无新帧：提示检查设备并暂停；③持续有新帧但模型无结果：提示识别未响应并暂停。关键姿态丢失与音频中断也暂停，并保留具体原因。

现有v0.1.2诊断起点可沿用：初始预热约3秒、取帧新鲜度约1.8秒、模型回包约2.5秒；后续按实测冻结，不把这些超时当作玩家动作窗口。慢帧只更新当前手位置，禁止跨长间隔插值出虚构命中。最终资格判定还需考虑关键姿态质量，不能仅以平均FPS代替。

暂停冻结游戏时间，恢复重新锁人和同步。网页内部切页不释放采集；明确停止摄像头、关闭整个网页才释放流和计算资源。镜头位置变化若无法自动可靠识别，应由用户主动重校准。

## 15｜隐私、动作安全与数据保存

默认只在本机浏览器处理视频，不上传、不录像、不做人脸身份识别。视频预览可关闭，关闭只隐藏显示，不表示停止识别；停止摄像头按钮必须实际释放输入。

本地保存设置、校准档案、最佳成绩与必要的匿名测试数据；提供清除。原始视频或完整关节时序只在明确开启的测试采集流程里保存，保存前说明用途和范围；默认导出摘要，不自动导出连续人体轨迹。

JSON 导出包含配置版本、聚合指标和经选择的事件记录；可附 CSV 汇总。普通用户流程不要求上传视频或注册账号。

动作保持小幅、低冲击；不奖励更大步幅。向后指令仅在玩家自行确认背后净空、校准通过后展示。单目摄像头不承诺检测地面防滑和完整家具边界，界面不能显示“环境已确认安全”。

## 16｜结算、乐句练习与重玩目标

### 16.1 结算优先级

首屏显示曲名、玩法/难度/配置、正式或辅助、总分与评级、最大连击、与同一纪录键个人最佳的差值。正式创造最佳时显示New Best；完整正式全连/全Perfect才显示相应徽章。

次层显示准确率、Perfect/Great/Good/Miss、保护数量、左右手与身体单位表现、早/晚趋势、乐句完成度。Z1细分方向错误和拒判；完整模型/阈值/性能详情折叠在测试报告，玩家首屏不堆叠算法信息。

每次给一条可执行建议：例如“B段右手下切最常漏，练第13–16小节”“入门已达A级，可试标准”。建议基于本次实际事件；若主要问题是系统保护，则建议改善输入，不把它误归因于玩家技术差。

### 16.2 乐句练习P0

从结算选择薄弱乐句，或曲前主动进入；范围按4/8小节选择。前导4拍倒数，不评分前导音符；循环之间有准备空段，每次清空动作候选、重建时间映射，旧事件不重复得分。

P0支持1.0原速与0.75练习速率。音频、音符目标和持续时长同步按播放速度变换，不能只放慢画面。评分窗口仍以真实毫秒计算，播放速率与谱面时钟关系记录在报告；速度变化产生独立辅助练习记录。变调/保调策略需标明，音频不支持时不能展示失效速度按钮。

练习不更新正式最佳；逐轮显示本段准确率、漏拍位置和变化。玩家能一键回原曲原配置整曲再试，不强制再走完整摄像头实验校准。

### 16.3 本轮成长范围

以本地纪录、S/A/B评级、全连、乐句改善与难度推荐形成重玩动力。曲库只有一首时不伪造已解锁新歌，不引入体力、付费复活或每日登录压力。

本地徽章P0只记录已有可验证事实；长期角色养成、皮肤、在线排行榜与日常任务P2。舞台/角色没有数值加分能力。

## 17｜Z 对照测试与指标定义

### 17.1 测试步骤

1. 开发自测：验证静止、接拍、挥切、每种负样本与前后各方向事件。
2. 小样本玩法测试：建议 5–8 名不同身高/经验的成人，使用当前 Mac，比较 XY/Z0/Z1；先验证交互和主要误判。
3. 冻结参数后保留验证：建议累计至少 12 名成人且包含至少 4 名未参与调参的人；固定场景与较难光照/衣着分别报告。人数是本轮探索建议，不是量产认证。
4. 每人至少做靠近 20 次、远离 20 次，以及静止和常见混淆动作；不同测试者均覆盖方向，不能用换人后的尺寸差当位移。
5. 三种可玩配置交错测试顺序，避免熟练度只偏向最后一种；记录疲劳、动作自然性、理解难度与主观公平感。

### 17.2 指标定义

| 指标 | 定义 |
|---|---|
| Z0 事件召回 | 被一对一匹配的真实前后移动 / 全部真实前后移动 |
| Z0 事件精确率 | 一对一正确匹配事件 / 所有输出事件；重复事件算额外误报 |
| Z1 全样本方向成功率 | 被正确检测且方向正确的试验 / 全部有效真实方向试验；拒判、漏检均计入分母 |
| Z1 方向作答准确率 | 正确方向事件 / 已匹配且给出方向的真实动作；必须与覆盖率一起报告 |
| Z1 覆盖率 | 有有效方向作答的试验 / 全部真实方向试验 |
| 方向混淆 | 靠近被判远离、远离被判靠近；另列 uncertain、无输出 |
| 负样本误报 | 每类非 Z 动作误报次数 / 该类动作次数；自然舞动另报每分钟误报 |
| 回位重复计分 | 一次计分动作及其回位产生的额外计分次数 |

匹配窗口和人工起始定义在验证前冻结。测试场即使能显示“正确率 100%”，只要大量拒判，不能作为方向玩法可用的结论。

## 18｜验收门槛与结论等级

以下为冻结前的需求目标，未实测项必须报告“待验证”。单元测试通过不代表真人可用。

| ID | 验收项 | v1.2要求 |
|---|---|---|
| AC01 | 本地启动 | Mac记录版本浏览器、模型/依赖本地化，断公网可玩 |
| AC02 | 主循环 | 授权/定位→选曲→选玩法/难度→倒数→完整音乐→结算→重试，真实摄像头裸手闭环 |
| AC03 | 双玩法 | Slash到面与Catch收环两套到拍规则清楚，独立谱面；新手能完成动作教学并说清区别 |
| AC04 | 音符 | 接拍不预放刷分、挥切按方向、双手不单手替代、保持一次结算、侧移避障有效覆盖 |
| AC05 | 内容矩阵 | 4份主曲XY、4份入门Z扩展、4份32秒对照齐全；不存在假曲卡或不可用按钮 |
| AC06 | 编排 | 两档难度有实际区别；自动冲突检查+真人可达/音乐性审核；Z/避障/保持恢复区正确 |
| AC07 | 手部识别 | 保留集接拍/挥切精确率与召回率目标均≥95%，单独报告模式与采样条件；保持/避障另报成功/拒判 |
| AC08 | Z0 | 前后两方向事件召回率≥90%、精确率≥95%；两方向召回差建议≤5个百分点 |
| AC09 | Z1 | 全样本方向成功率≥85%、作答准确率≥95%、覆盖率≥90%；两方向分别报告 |
| AC10 | 干扰与回位 | 关键负样本每类≥50次、误报率≤5%；自然非Z误报≤0.2次/分钟；100次回位无额外计分 |
| AC11 | 评分与纪录 | 满分/边界/Pair部分分/持续单位/保护分母可复核；不同玩法、难度、配置、规则与输入隔离 |
| AC12 | 完成与练习 | 普通Miss不强制中止；自然曲终结算；可练薄弱4/8小节并回整曲；速度同步且辅助不覆盖正式 |
| AC13 | 输入连续性 | 实验室→大厅→选曲→舞台→暂停→结算反复10轮，流/模型保持正常、无新增重复流或旧光标误触 |
| AC14 | 误触与异常 | 弹层/换页后必须手离热区再停留；无新姿态不继续计停留；实际断流、后台、休眠正确暂停恢复 |
| AC15 | 性能诚实 | 分报采集/推理/渲染；慢帧与断流提示不同，辅助不扩大判分窗、不虚构轨迹；第14节目标有数据 |
| AC16 | 视觉体验 | 一套原创科技舞台、模式图例、低特效读谱；角色/特效不遮目标，不把视觉Z当玩家距离 |
| AC17 | 真人真实性 | 摄像头模式与模拟明显分开，模型预测不当人工标签；玩法观察与独立保留集结果分开报告 |

结果分层：“双玩法流程可用”“XY识别通过”“Z0通过”“Z1实验通过/未通过”，每项有独立证据。当前已有跨页面取帧修复不自动满足AC13的10轮新流程要求。

玩法观察建议先5–8名成人，记录首次两玩法理解、完成率、误触、愿意再玩及原因；不把小样本意见包装为普遍留存结论。Z识别仍按第17节完整保留验证开展。
