# 《星跃律动》体感舞蹈游戏需求说明书

版本：v1.0 · 策划评审稿  
日期：2026-10-20  
适用团队：产品、游戏策划、动作识别、客户端、音频、美术、测试、内容制作  
暂定英文名：Pulse Stage；中英文名称均需另行核名。

> 产品主张：用双手打出节拍，用身体带动舞台，用一次小幅前后律动释放空间脉冲。
>
> 核心约束：使用安卓手机的单目 RGB 摄像头，无手柄、穿戴或深度设备。Z 轴只接受“发生了一次前后移动”的无方向事件，绝不要求系统判断玩家是在向前还是向后。

## 01｜文档依据、边界与默认假设

### 1.1 已确认的需求

1. 为游戏机策划内置的舞蹈类体感游戏。
2. 通过安卓手机摄像头识别人身动作，玩家空手游玩。
3. 参考 Nex Playground 的 Starri 的玩法体验与美术方向。
4. 融入真实的 Z 轴身体运动；当前识别能力无法区分前后方向。

### 1.2 本稿的产品假设

| 项目 | 本稿默认方案 | 评审影响 |
|---|---|---|

## 02｜产品定位与体验目标

### 2.1 游戏定位

一款电视大屏上的轻舞蹈节奏游戏。玩家通过挥臂、接拍、身体侧移和少量纵深律动完成音乐表演。谱面把动作组织成有节奏的短舞段，使玩家感受到连续舞动，而不是零散地拍打屏幕。

游戏以“打得准、动得顺、看起来像在表演”为目标。评分只评价已定义且能稳定识别的动作，不以整套舞姿相似度或角色动画作为隐藏判分依据。

### 2.2 三个体验支柱

| 支柱 | 玩家感受 | 必须落实的设计 |
|---|---|---|
| 容易进入 | 不会跳舞也能跟上 | 免握持操作、短教学、舒适触达区、不失败退出 |
| 节奏爽感 | 每一次挥动都能听见、看见反馈 | 清楚的击中面、可靠时间轴、即时光迹与声音 |
| 空间律动 | 身体参与音乐高潮 | X/Y 手臂动作与少量无方向 Z 脉冲形成乐句 |

### 2.3 典型使用场景

- 一个人下班后，选一首 2–4 分钟的歌曲快速放松。
- 家长和孩子轮流挑战同一曲目，比较完成率和个人进步。
- 聚会时选取 60–90 秒精华段落，轮流争取最高分。
- 节奏玩家练习固定乐段，冲击个人最佳与全连。

## 03｜核心循环与游戏模式

### 3.1 单局循环

启动 → 连接与站位 → 选择歌曲/难度/动作配置 → 首次动作教学 → 3 秒准备 → 演奏 → 结算 → 重试、换歌或换人。

演奏内循环：提前读谱 → 身体准备 → 在音乐节点动作 → 音符判定 → 连击与舞台反馈 → 下一组舞段。

### 3.2 模式规划

| 模式 | 内容 | 分数规则 | 版本 |
|---|---|---|---|
| 快速开跳 | 单曲、三档难度、可开关纵深 | 个人最佳，可比较同配置成绩 | 首发 |
| 舞段练习 | 分段循环，支持 0.75/0.9/1.0 倍速 | 练习分，不进正式纪录 | 首发 |
| 轮流派对 | 2–4 人轮流挑战同一段落 | 同配置竞技；不同配置只并列展示 | 首发 |
| 连续歌单 | 连续 3 首或自选歌单，中间休息 | 各曲成绩加歌单总结 | 后续 |
| 双人同屏 | 每人独立区域与谱面，竞分或合作 | 独立难度时不直接判胜负 | 后续，须通过多人识别验证 |

首发把接拍和挥切组织在同一套舞段里，由难度控制组合复杂度。先不拆成两套独立内容库，减少初学者的模式选择负担。

## 04｜空间、设备与开局校准

### 4.1 手机与电视关系

- 手机需要固定支撑，游玩中不手持；支撑物不是动作输入设备。
- 默认使用固定朝向的 RGB 摄像头。前摄和后摄均可候选，以目标机型视场、可用帧率和安装便利性选择；首发认证组合必须固定。
- 电视是主要视听输出，手机屏幕承担连接、摄像头权限、取景调整与紧急暂停。
- 手机与电视主机分离时，采用本地会话配对；不依赖公网处理动作。配对、重连和时钟同步必须独立验收。
- 不把普通无线镜像当作默认竞技链路。若支持镜像播放，作为单独输出模式校准与认证。
- 首次权限授予和设备配对可使用手机触屏，之后的游戏内导航和游玩全程支持空手完成。

### 4.2 空间要求

建议原型起点为：镜头前约 2–3 米、玩家左右各能安全伸臂、前后各可小步移动的区域。**这些不是通用硬件保证**：实际距离由视场、玩家身高和现场取景决定，不按固定米数强制开局。

开局必须验证头、手臂活动范围和髋部可见；标准全身谱面还要求膝踝可见。界面用取景轮廓提示“抬高手试一下”“向两侧伸展一下”，检查动态范围，而不只检查静止站姿。

纯单目画面不能可靠确认地面是否防滑、身后是否有家具、房间是否有实际净空。游戏应提示玩家自行清理活动区域，不展示“已确认安全”之类的错误保证。

### 4.3 校准步骤

| 步骤 | 玩家动作 | 系统得到什么 | 失败处理 |
|---|---|---|---|
| 人体锁定 | 正面自然站立约 2 秒 | 玩家 ID、中心点、可见关节 | 给出移动镜头/补光提示 |
| 舒适范围 | 左右伸手、抬手、轻侧移 | 触达区、身体比例、动作基线 | 重新校准或切轻量模式 |
| 左右确认 | 跟随示范抬起指定手 | 解剖学左右与镜像显示一致 | 切换镜像映射后复验 |
| Z 能力检测 | 小步前后律动 3 次，每次间隔稳定站立 | 无方向事件幅度与噪声水平 | 关闭 Z，加载替代谱面 |
| 视听/动作同步 | 按节拍完成 8–12 次简单拍点 | 当前链路的综合时间偏差 | 可重试或使用设备默认档 |

Z 检测不要求玩家证明“向前正确、向后正确”。示范必须展示前移和后移都能触发相同脉冲。

每次更换玩家重新做人体与动作范围校准；更换镜头位置、输出链路、电视模式或音响设备后重新校准对应部分。范围基线只在稳定待机或无动作空段缓慢更新，动作发生期间冻结，防止归一化把有效位移消除。

## 05｜画面坐标与音符呈现

### 5.1 坐标约定

- 玩家面对摄像头；画面采用镜子式交互：玩家举自己的左手，对应屏幕左侧的左手标记。
- 识别层保留原始镜头坐标和解剖学关节标签；映射层统一处理旋转、裁切、镜像和电视显示，其他系统不能各自再镜像一次。
- 手部目标用“相对玩家校准中心、相对舒适范围”的归一化坐标定义，避免按电视像素要求儿童和成人达到同样位置。
- Z 是独立无方向事件轴。音符的透视运动只表示到拍时间，不代表玩家实际离镜头的距离。

### 5.2 读谱方案

采用 2.5D 舞台：远处出现的音符沿透视路径接近固定击中面。击中面的可达区域与手部光标保持稳定映射，不随相机装饰运动漂移。

屏幕划分为左、右两侧的高/中/低目标区，共六个主要读谱区；新手只使用四个舒适区。目标位置可以平滑过渡，但不要求玩家追逐过小的随机点。

普通音符提前约 1.5–2 秒进入清晰可读状态。Z 音符先有准备提示，确保从第一眼清楚看懂到判定点至少 2 秒；新手建议 3 秒。高速难度缩短手部音符预读时，Z 保留自己的最短预读时间。

角色置于舞台下方或透视远端，不能遮挡击中面和未来一组音符。玩家实拍预览可关闭；关闭后仍显示识别状态和离框提示。

## 06｜动作与音符需求

### 6.1 动作字典

| ID | 名称与外形 | 玩家动作 | 判定信号 | 主要反馈 |
|---|---|---|---|---|
| A01 | 接拍：实心圆芯+闭合环 | 指定手到达目标区 | 高置信度手腕进入区域并满足短暂驻留；不能靠长期预放手得分 | 光环合拢、清脆短音 |
| A02 | 挥切：菱形+方向缺口 | 指定手按箭头挥过目标 | 手腕轨迹穿过区域，方向与速度达标 | 切线、碎片和挥切短音 |
| A03 | 双手拍：两个相连目标 | 双手分别到达对应区域 | 两只手各自命中、时间差在窗口内 | 两道光轨汇合 |
| A04 | 延音：带尾迹的接拍音符 | 手跟随缓慢移动轨迹 | 有效跟随时间占比 | 连续发光与尾迹推进 |
| A05 | 侧摆：侧边弧门 | 肩髋中心侧移或侧倾 | 躯干中心横向变化及姿态约束 | 舞台横向展开 |
| A06 | 纵深脉冲：双层同心环+身体图标 | 保持面向镜头，小幅前后律动一次，任一方向都可 | 无符号 Z 事件、起始时间和置信度 | 环向四周扩散、舞台固定脉冲 |
| A07 | 低位律动：下方压缩条 | 轻屈膝降低身体 | 髋部下降配合膝部姿态 | 舞台压缩再回弹 |

A01–A06 为标准首发核心动作；A07 先用于练习和后续内容，待屈膝与 Z 的混淆验证通过再进入正式谱面。不安排腾空跳跃、跪地、快速转身或必须后退的大步动作。

### 6.2 细化判定规则

**接拍**：需要从目标区外进入，或在准备阶段从指定待机区移动到目标；在音符生成前一直停在目标上不能自动 Perfect。判定时间为进入有效区域的时间。原型驻留确认约 60–100ms，确认完成后回溯到进入时间，避免把确认延迟算成玩家迟到。

**挥切**：使用连续有效采样之间的轨迹线段与目标区域求交，避免快速挥手越过目标但采样点没有落在圆内导致漏判。轨迹跨越较长失踪间隔时不做穿越补算。方向使用 XY 运动向量判断，初始角度容差建议 ±45°，具体需实测。

**双手拍**：两只手分别产生子判定，间隔建议不超过 120ms。两手完全有效取较低档作为整枚评价；仅一手命中时整枚 Miss，可保留半分，规则在结算说明中公开。不得用单手跨区模拟双手。

**延音**：整枚只结算一次，跟随覆盖率建议 ≥90% 为 Perfect、≥75% 为 Great、≥50% 为 Good，其余 Miss；首尾时间和有效跟随区域同时参与，短暂抖动有约 100ms 宽限。不给每帧叠分。

**侧摆**：只要求舒适范围内的小幅侧移/侧倾。首发不做有碰撞惩罚的强制躲墙；未完成侧摆作为音符 Miss，视觉上仍能继续表演。

**动作幅度**：每种动作均有校准后的最小有效幅度与舒适上限。上限只控制特效强度，不奖励过度挥臂、跑动或大幅后退。

## 07｜Z 轴核心机制：纵深脉冲

### 7.1 设计契约

向前和向后都可能产生一个完全相同的 `DepthPulse` 事件。游戏只消费“本次前后移动发生了”的信息，不消费位移正负号，也不根据模型的深度数值自行推断方向。

玩家看到的是“身体前后动一下”，不是“向前冲”“向后躲”。完成动作后，舞台播放设计好的脉冲或穿越动画；该动画是固定反馈，不能让玩家误以为系统实时测出了其前后方向。

### 7.2 三种候选表现

| 表现 | 玩家理解 | 输入能力 | 版本建议 |
|---|---|---|---|
| 空间脉冲环 | 在拍点上让身体前后动一下 | 单次无方向位移事件 | 首发唯一正式 Z 音符 |
| 乐句穿越 | 一次律动让舞台切到下一幕 | 与脉冲环完全相同 | 首发作为视觉变体，不增加规则 |
| 连续空间律动 | 按多个拍点重复前后律动 | 多次可分离事件 | 后续；恢复时间与误触发验证后启用 |

不做前后双轨、不做“靠近才能接到 / 远离才能躲开”、不做向前推手和向后拉手的深度判定。单手前伸也不能替代全身纵深事件。

### 7.3 玩家教学用语

“看到这个环，保持面向屏幕，身体前后轻轻动一下。向前、向后都可以。动作完成后，趁没有音符时回到舒适站位。”

示范动画依次展示向前一步、向后一步，二者触发同样的成功反馈。不要用单向箭头作为 Z 图形主语义；采用对称双向图标加无方向扩散环。

### 7.4 事件状态机

`未就绪 → 稳定待机 → 可触发 → 候选移动 → 事件确认 → 恢复锁定 → 稳定待机`

| 状态 | 进入条件 | 行为 |
|---|---|---|
| 未就绪 | 未校准、低置信度、设备晃动或离框 | 禁止输出 Z 事件 |
| 稳定待机 | 身体可见且运动能量低 | 采集局部噪声基线 |
| 可触发 | 稳定达到约 300ms，已过恢复锁定 | 等待合格动作；是否计分由谱面窗口决定 |
| 候选移动 | 无方向深度运动信号超过进入阈值 | 记录首次过阈时间，验证持续性和混淆因素 |
| 事件确认 | 有效信号持续约 100–180ms，排除条件通过 | 输出一次带唯一 ID 的事件，时间回溯到首次过阈 |
| 恢复锁定 | 每次确认后至少约 800ms；谱面还预留回位空段 | 回位、摆动余波均不能再次输出计分事件 |

退出运动使用低于进入阈值的迟滞阈值。锁定期结束后仍需重新稳定，持续走动、持续晃动不得按固定时间间隔自动产出多次事件。

**能力边界必须明确**：只有无方向运动信息时，系统无法证明玩家已回到原来的物理站位。这里的“稳定”仅说明当前停稳；回位是玩家引导动作，不能伪装成已检测到原点。通过低频谱面、回位空段、取景边界和教程减少累计漂移；若日后需要强制验证原点，必须增加并验证额外定位能力。

### 7.5 识别信号与误触发排除

本稿把用户提供的“能检测前后移动”视为待接入能力，而不是已经证明量产可用。若尚无该模块，必须先做概念验证。

可研究的候选信号包括：多关节一致的表观尺度变化、躯干整体运动、人体区域光流等。单独用肩宽变化、人体框变大/变小或某个关节的模型 Z 值，不能作为可靠的全身前后移动判据。

需要负样本验证：原地摆臂、扩胸、身体转侧、弯腰、屈膝、横移、相机抖动、自动变焦/裁切、其他人经过。动作排除不成功时应降低置信度并暂停 Z 判定，而不是猜一个方向。

MediaPipe 的官方文档说明其输出图像关节点和三维关节点；其中深度/世界坐标以髋部中点为原点。因此，**从这些输出直接得到玩家相对摄像头的整体前后平移并无保证**，仍需单独验证。[Android Pose Landmarker 文档](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/android)

### 7.6 Z 谱面约束

1. 新手约每 8–16 拍最多一个，标准约每 8 拍最多一个；挑战档也必须满足实际恢复间隔。
2. 两个 Z 判定点初始至少间隔 3 秒。编辑器按毫秒检查，不能只按 BPM 推导拍数。
3. Z 的前 500ms、后 1000ms 不安排强制手部目标、侧摆或屈膝；保留看提示、稳定和回位时间。
4. 回位区间只显示“轻松回位”提示，不计分、不产生第二枚 Z 音符。
5. Z 不与持续手部延音重叠。即使原型能同时识别，也先保护身体动作的自然性。
6. 单曲 Z 数量建议占全部评分单位的 5%–10%；用在重拍、乐段衔接、高潮，不作为持续赶路机制。
7. 玩家校准只能在安全小幅动作下通过；不能通过不断要求更大步幅来弥补模块识别不足。

### 7.7 无 Z 配置与运行中故障

- 进入曲目前提供“标准律动”和“原地律动”两种配置。
- 原地律动使用预先编排的替代音符，如双手向侧面打开后接拍；不宣称这仍然是 Z 识别。
- 两种配置使用不同谱面 ID 与个人纪录，界面明确标注。
- 校准失败时直接推荐原地律动，保留正常的游玩和评分体验。
- 标准律动运行中 Z 模块持续无效：暂停 → 说明原因 → 重新校准，或重新开始该曲的原地版本。不得悄悄替换正式谱面继续上传可比成绩。
- 练习模式可动态替代并继续，结算标注辅助模式。

## 08｜舞蹈编排与难度

### 8.1 舞段组织原则

用 4 拍或 8 拍组成可记忆的动作短句。先重复，再变化，高潮再叠加；手臂从上一动作结束位置自然过渡，不要求突然跨越身体极限。

常用结构：左接拍 → 右接拍 → 左上挥切 → 右下挥切 → 双手打开 → 侧摆 → 休止 → 纵深脉冲。角色示范动画与此动作结构一致，但不追加未评分的强制步法。

### 8.2 三档难度

| 维度 | 入门 | 标准 | 挑战 |
|---|---|---|---|
| 手部节奏 | 多为一拍一个，明显休止 | 混入半拍与连续挥切 | 局部半拍，少量短促切分 |
| 目标区域 | 中部四个舒适区 | 六区，少量跨区 | 六区连续组合，仍有限幅 |
| 指定左右手 | 清晰交替，少量任意手 | 指定手为主 | 更复杂但可读的交替 |
| 纵深 | 教学后开启，低频 | 在乐句节点使用 | 增加节奏变化，不增加危险步幅 |
| 侧摆 | 少量、幅度小 | 与手臂短句交替 | 连续短句，保留恢复 |
| 预读 | 约 2 秒以上 | 约 1.7–2 秒 | 约 1.5–1.8 秒；Z 独立保障 |
| 体力 | 完成一曲负担低 | 中等持续运动 | 节奏更复杂，不靠持续大幅运动提难 |

难度与体力强度分别标识。高难不等于高冲击；提供低幅度、无屈膝配置，配置变化需匹配对应谱面纪录。

### 8.3 示例：120 BPM、16 小节、32 秒试玩谱

每小节 4 拍，每拍 0.5 秒。小节起点时间为演奏音频时间，不包含开局倒数。

| 小节 | 起点 | 设计内容 | 目的 |
|---|---:|---|---|
| 1–2 | 0s | 左右中位接拍；留出交替准备 | 学会看区域与拍点 |
| 3–4 | 4s | 左上、右下挥切；重复一次 | 学会方向与轨迹 |
| 5 | 8s | 双手接拍、两拍休止 | 建立舞段呼吸 |
| 6 | 10s | 第 1 拍 Z 脉冲；提前从 8s 提示；10.5–12s 回位空段 | 第一次纵深体验 |
| 7–8 | 12s | 左右挥切形成同向流动 | 从身体回位接到手臂动作 |
| 9–10 | 16s | 左右侧摆，各配一组简单接拍，错开判定点 | 增加躯干参与 |
| 11 | 20s | 第 1–2 拍双手打开，之后休止；从 20s 提示下一 Z | 做高潮准备 |
| 12 | 22s | 第 1 拍 Z 脉冲，之后回位空段 | 与音乐重拍同步切景 |
| 13–14 | 24s | 重复第 3–4 小节并稍变位置 | 强化掌握感 |
| 15–16 | 28s | 双手接拍，最后一拍结束姿势，不额外判姿势 | 完成表演 |

该段是可制作样例，不是量产密度标准。第一轮原型至少比较“有 Z / 原地替代”两版的理解、成功率和舞动感。

## 09｜时间判定、得分与公平性

### 9.1 判定窗口：原型初值

下列数值均以校准后的事件时间相对目标拍点的绝对误差计算。区间按从高到低依次匹配；动作空间、方向或质量条件未通过则不能仅凭时间得分。

| 评价 | 接拍/挥切 | 纵深脉冲 | 基础分系数 |
|---|---:|---:|---:|
| Perfect | ≤90ms | ≤160ms | 1.00 |
| Great | >90–150ms | >160–260ms | 0.80 |
| Good | >150–230ms | >260–380ms | 0.50 |
| Miss | 超窗或动作不合格 | 超窗或无有效事件 | 0 |

侧摆初始沿用 Z 的时间窗口，空间阈值独立校准。延音与双手拍按第 6 节特殊规则结算。最终窗口要结合采样频率、实际延迟残差和用户测试锁定；尚未验证前不可宣传毫秒级精准评分。

Z 更宽的窗口是因为全身动作与事件确认更慢，不代表后台默认补成功；其评价不能与手部延迟统计混为一谈。

### 9.2 总分公式

`总分 = round(1,000,000 × Σ(音符权重 × 实得系数) / Σ(音符权重))`

- 每个评分单位默认权重 1，延音和双手音符也各算一个；特殊权重须写入谱面并在版本内固定。
- 满分 1,000,000。Combo 不额外乘分，避免一次漏拍被分数和倍数双重惩罚。
- Perfect、Great 增加 Combo；Good 有分但中断 Combo；Miss 无分并中断。教程明确说明。
- 全连：全曲无 Good/Miss，所有评分单位均 Perfect/Great；另设“全 Perfect”徽章。
- 初版评级：S ≥95%、A ≥85%、B ≥70%、C ≥50%、D <50%。评级仅是本稿建议。
- 双手拍部分命中可给 0.5 系数，但整体归为 Miss，断连；准确率按实得分比例计算。
- 练习变速、动态辅助、追踪中断保护和谱面中途变更都需标记，不能进入普通正式纪录。

### 9.3 事件分配与防重复

- 每个离散动作事件最多消耗一次，每个音符只产生一次最终结算。
- 同一只手一次挥切不能贯穿多个相邻音符获多次分，除非谱面明确定义独立分段事件，首发不使用该特例。
- 优先匹配同动作类型、同指定手、有效区域相交且时间差最小的未结算音符；同差值时优先较早音符。
- 回程挥臂、Z 回位、追踪恢复的坐标跳变、网络重复包不能触发额外得分。
- 禁止在置信度丢失期间用长距离插值伪造命中。

### 9.4 识别故障保护

短暂低置信度时显示轮廓变暗，不能通过预测坐标生成评分动作。涉及该时段的音符标记为“系统保护”，不补 Perfect、不静默记玩家 Miss，当前局转为辅助成绩，保留中断前有效累计分和统计。

初值为：连续关键关节失效约 300ms 暂停；连接断开或镜头移动立即暂停。暂停时冻结音乐、谱面和评分时间轴。恢复先稳定锁定身体，再倒数，从最近安全乐句点重开；回放区间的旧成绩作废并重算，禁止重复加分。恢复后的整局不进入正式最佳或排行榜。

玩家主动暂停也使用同一成绩资格规则。轮流派对中正式比较可选择重开完整段落，避免暂停改变挑战条件。

### 9.5 延迟与时钟

以音频播放时间为唯一谱面主时间轴。手机拍摄时间、识别结果时间、主机接收时间分开记录。评分按映射到音频时间轴的拍摄/事件时间计算，不按网络包到达时刻计算。

跨设备会话定期估计时钟偏移及漂移，使用单调时钟。迟到事件只允许在有界缓冲期内完成最终结算；超过上限进入技术故障保护，不回改已经展示较久的分数。

同步策略二选一并固定实现：
1. 技术链路分段测量后补偿，玩家校准仅修正剩余偏差；或
2. 玩家端到端校准得到综合偏差，不再重复减去同一段延迟。

需分别保存输出链路档案和动作确认延迟参数。更换电视游戏模式、音箱、蓝牙音频或镜像链路后，旧偏移不能自动当作有效。

## 10｜裸手导航与页面流程

### 10.1 导航规范

- 非演奏页面使用手腕光标：指向大按钮并稳定停留约 1 秒确认，环形进度显示剩余时间。
- 同屏一次只显示少量主操作；列表按页翻，不让玩家用空中精细滚动定位几十首歌。
- 返回使用固定角落按钮；退出曲目需在暂停页二次确认。
- 演奏时关闭普通菜单光标，避免挥臂误点。
- 暂停姿势采用“双腕在头部以上较窄区域保持约 1.5 秒”，谱面禁止安排持续同姿势；仍需专门验证举手音符误触率。手机触屏提供暂停备选。
- 丢失跟踪自动暂停不依赖暂停手势识别。
- 首次摄像头权限拒绝后说明开启路径，允许返回游戏机首页，不反复弹窗。

### 10.2 页面需求

| 页面 | 主要内容 | 主操作 | 状态与异常 |
|---|---|---|---|
| 启动/连接 | 配对码、设备状态、权限 | 连接手机、使用已配对设备 | 无设备、超时、版本不匹配、重新连接 |
| 站位校准 | 实拍轮廓、身体可见性、活动范围 | 开始校准、重试、原地模式 | 太近/太远、暗光、多人入镜、Z 无效 |
| 主入口 | 快速开跳、练习、轮流派对、外观、设置 | 进入模式 | 首次教学、上次会话恢复提示 |
| 选曲 | 封面、曲名、歌手、时长、BPM、难度、体力标识、下载状态 | 试听、翻页、筛选 | 无曲目、未下载、下载失败、授权不可用 |
| 曲目准备 | 难度、动作配置、最佳纪录、所需空间 | 开始、练习、返回 | 配置不支持、需要重新校准 |
| 演奏 | 音符、击中面、手部光标、分数、Combo、识别提示 | 动作游玩、暂停 | 离框、遮挡、连接/性能故障 |
| 暂停 | 原因、继续、重试、换歌 | 继续或退出 | 标记本局成绩资格变化 |
| 结算 | 评级、准确率、最佳连击、判定分布、Z 完成数 | 再来、换歌、换人 | 辅助成绩、未完成、存档失败 |
| 外观 | 角色、配饰、舞台预览 | 试穿、应用 | 未解锁、资源缺失回退默认 |
| 设置 | 音量、镜像、取景预览、特效强度、校准、隐私 | 保存、恢复默认 | 明确说明是否影响成绩配置 |

### 10.3 演奏 HUD

以 1920×1080 为设计基准：顶部展示曲目进度和分数，Combo 位于不挡音符的上侧；中央约 65%–75% 为主要读谱范围；下方为角色与短动作提示；角落预览建议不超过画面宽度 18%，可隐藏。

所有关键文字和按钮落在约 5% 的安全边距内。普通提示建议 32–40px，关键动作指令 48–64px，判定文字 56–80px；最终按 2–3 米电视观看实测调整，不直接套用手机字号。

Z 提示固定在主要视线附近，不能只放在角落；提示覆盖时主动清空附近手部音符，避免争夺注意力。

## 11｜美术与视听规格

### 11.1 方向：光轨演出舞台

沿用参考中的几何节奏音符、深色空间、明亮击中反馈和可装扮角色，建立原创角色与舞台。不直接复制 Starri 角色轮廓、服装、UI、谱面、图标或音乐素材。

风格依据：音乐体感和截图的击中反馈需要较高能量；电视远距离读谱要求低信息密度；角色收藏需要完成度明确的卡通渲染。因此采用“活跃、表面整洁、读谱区域稀疏、关键图形厚重、角色轻松”的组合。

舞台叙事是玩家用动作激活光轨装置：每次击中发出一段光，连续成功使舞台逐层点亮，纵深脉冲把一整层空间展开。

### 11.2 色彩与形状

| 角色 | 建议色值 | 使用规则 |
|---|---|---|
| 背景 | #101820 | 低亮度舞台底色，保证目标对比 |
| 非演奏面板 | #26333B | 选曲、设置和结算容器 |
| 正文 | #F4F5F0 | 非渐变文字，避免细字 |
| 左手 | #63D6EE | 配圆形芯与左手标记 |
| 右手 | #FFB16B | 配菱形芯与右手标记 |
| Z 脉冲 | #F2DC8A | 双环和身体图标，独立于左右手 |
| 系统故障提示 | #F29A93 | 配文字与状态图标，不能只靠红色 |

参考的霓虹感集中在音符、光迹和击中瞬间；不把全部按钮和页面做成发光渐变面板。手别必须同时用形状、L/R 或图标编码，色弱模式可更换配色并保留形状。

颜色是建议设计值，需在实际电视、SDR 和低亮度环境下验证。关键文字目标对比度 ≥4.5:1，大号图形与必要边界 ≥3:1。

### 11.3 角色、场景与资产

- 角色：原创风格化 3D 或 2.5D 卡通人物，中性、活力、便于家庭接受。首发建议 2 个基础角色、各 3 套配色，配饰不影响动作轮廓。
- 角色姿态：上半身可跟随受约束的识别姿态，丢失关节平滑回待机；脚步用预设动画。不得展示被解释为精确捕捉的实时前后走位。
- Z 表现：每次合格事件播放固定的“聚能—扩散”动作。普通阶段角色 Z 位置保持稳定。
- 教学：专门制作左右手、挥切、双手、侧摆、Z 正反两例、回位、暂停动画。
- 首发舞台建议 3 套：光轨演播厅、几何城市、星海露台。透视相机保持固定；高强度切景仅在空拍或乐段过渡。
- 音符图形和 HUD 使用原创矢量或引擎图形资产；封面来自授权曲目素材；角色与背景为原创制作或清楚标注许可来源的资产。
- 封面缺失用曲名与统一排版的正式文字封面回退；角色资源失败用默认已安装角色；不可显示灰色占位框作为交付画面。
- 中文字体与拉丁数字分别选取清楚可读且获发行许可的字体；标题可略带舞台感，正文不用装饰字体。确认实际字符集和授权后再锁定字体文件。

### 11.4 特效、声音与反馈

| 时机 | 动效起点建议 | 音频要求 |
|---|---|---|
| 手腕移动 | 立即显示短尾迹，减少拖尾长度 | 不持续发出噪声 |
| Perfect | 约 120–180ms 的形状破碎与亮点 | 干净、有辨识度，不盖过音乐 |
| Great/Good | 更弱的形状反馈 | 保留节奏完成感 |
| Miss | 目标暗化并消散 | 短、轻，不发羞辱式声音 |
| Z 成功 | 约 300–500ms 的同心环扩散 | 低频短脉冲，可独立调低 |
| Combo 里程碑 | 10/25/50/100 连激活舞台层 | 少量庆祝音，不每次打断歌曲 |
| 结算 | 评级和个人最佳分步显现 | 音乐收尾后播放，不截断尾音 |

提供音乐/效果音独立音量；不强制语音。提供低特效和降低动态模式：移除屏震、快速切景和大范围闪光，保留必要的到拍运动与文字提示。不得用高频闪烁承担节奏提示。

导航按钮必须覆盖普通、指向、停留进度、触发、不可用、处理中、成功、错误状态；体感没有 hover 指针设备，但有明确的指向和焦点态。停留中抖出区域允许短暂容错，离开后进度取消，避免误选。

## 12｜歌曲、谱面和内容管线

### 12.1 首发内容建议

- 12 首完整曲目，建议 2–4 分钟；另提供其中 4 首的 60–90 秒派对段。
- 每首入门/标准/挑战三档，标准律动与原地律动均需人工检查。
- 三档共 36 个难度谱面；两种动作配置形成 **72 个可游玩配置**，派对节选另外生成配置并单独 QA。原地版可由同源谱面按规则派生，不代表不用审核。
- 曲风覆盖流行电子、轻快舞曲、复古律动等；优先节拍清晰、乐句明确、适合家庭的内容。
- 内置 1 首专门的教学曲/短段，使用自有或已确认授权音乐。

曲目清单尚未选定，不能把参考视频中的歌曲视为可直接使用。内容排期需要先确认可发行地域、终端、离线包、宣传素材及更新范围的授权覆盖，由项目授权负责人落实。

### 12.2 谱面数据要求

歌曲层：歌曲 ID、音频资源和校验、采样率、时长、拍点偏移、BPM/变速表、拍号、小节、预览片段、授权可用状态。

谱面层：谱面 ID/版本、难度、动作配置、评分规则版本、音符列表、动作安全约束、角色动作轨、舞台事件轨、测试状态。

音符层：唯一 ID、目标音频时间、类型、指定手、归一化目标位置、区域半径、XY 挥切方向、持续时长、评分权重、预提示时间、互斥/恢复区间、替代配置对应关系。

`DepthPulse` 音符不得含 `forward/backward` 之类的方向条件。演出切景可以有设计好的纵深镜头参数，但必须与玩家识别字段分离。

### 12.3 制作流程

选曲与授权 → 拍点分析 → 编舞动作短句 → 标准谱面 → 入门/挑战改编 → 原地替代 → 动作可达性检查 → 真机试玩 → 音画同步与误判检查 → 内容负责人签入版本。

自动分析只辅助标记拍点与候选音符，正式谱面需要人工编排和身体试玩。

### 12.4 谱面编辑器最小能力

1. 音频波形、拍点网格、变 BPM 和偏移编辑。
2. 六区目标与动作轨并列预览；实时查看左右手轨迹是否连续可达。
3. Z 无方向类型、独立预提示、恢复空段和原地替代关系。
4. 校验 Z 间隔、冲突动作、超舒适范围、音符重叠、暂停姿势冲突、资源缺失。
5. 逐段循环、慢放、设备回放和一键定位失败案例。
6. 谱面与评分版本锁定，发布后改动产生新版本，不覆盖旧纪录的含义。

## 13｜动作识别与客户端技术需求

### 13.1 模块划分

`RGB 采集 → 图像方向/裁切处理 → 人体关键点与置信度 → 玩家跟踪 → 动作特征/事件 → 时间同步 → 谱面判定 → 视听与结算`

手机和主机分离时，手机负责至动作事件输出；主机负责音频主时间轴、判定、渲染和存档。可发送关节坐标支持光标和角色，但不需要传输原始相机视频。若显示手机实拍预览，另走可关闭的本地视频通道，不让视频编解码阻塞动作数据。

如主机为安卓手机形态，上述模块同机运行，省去网络时间同步；不改变动作事件和谱面接口。

### 13.2 候选技术与限制

可用 MediaPipe Pose Landmarker 或项目已有 SDK 做原型，优先验证手腕、肘、肩、髋、膝、踝；不依赖指尖精细识别。MediaPipe 提供 Android 实时流模式、时间戳与姿态结果接口，适合做候选基线，但不等于已满足产品性能。[官方文档](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/android)

ML Kit 也提供 33 点姿态能力；其文档说明全身可见时效果更佳，且 API 仍有 Beta 限制。仅作为备选评估，不预先承诺其多人或 Z 能力。[官方文档](https://developers.google.com/ml-kit/vision/pose-detection)

首发对指定机型及镜头组合做认证，不承诺所有安卓手机都支持。安卓版本、芯片、内存和引擎选型在目标硬件确定后锁定；原型记录 CPU/GPU/NPU 使用、温升、耗电和长时稳定性。

### 13.3 输入输出契约

| 数据 | 必需字段 |
|---|---|
| 姿态帧 | 会话 ID、帧序号、采集时间、玩家 ID、关节坐标/可见性、镜头方向、跟踪质量 |
| 动作事件 | 唯一事件 ID、玩家 ID、动作类型、起始/结束时间、置信度、指定手/轨迹、质量状态 |
| Z 事件 | 类型 `DepthPulse`、起始/确认时间、无符号强度、置信度、排除原因、恢复锁定状态；**无方向字段** |
| 设备状态 | 镜头移动、帧率、处理耗时、时钟质量、网络状态、温度降级状态 |
| 判定结果 | 音符 ID、匹配事件 ID、评价、时间误差、失败/保护原因、评分版本 |

强度字段用于判定合格阈值和有限的特效变化，不表示米数。SDK 若内部带有方向估计，适配层也不能把它当成正式游戏条件。

跨设备传输需要序号、去重、超时、会话校验和重连机制；乱序按采集时间排序，超过可接受时间界限进入保护。旧会话事件和旧玩家事件一律丢弃。

### 13.4 性能目标与降级顺序

以下是待测目标，必须在最低支持机型与最差认证输出链路上验证：

| 指标 | 原型/验收目标建议 |
|---|---|
| 采集 | 至少稳定 30fps；分辨率按识别效果和负载选择，不盲目提高 |
| 有效识别输出 | 常态 ≥25 次/秒；长时间低于 20 次/秒应提示并停止正式计分 |
| 采集到事件可用 | 手部事件处理链 P95 ≤120ms，Z 确认时间另外统计 |
| 手部动作到可见反馈 | 指定认证链路 P95 ≤150ms；含电视输出，须外部测量 |
| 校准后同步残差 | 中位绝对误差 ≤40ms，P95 ≤80ms，须以统一参考测量 |
| 渲染 | 目标 60fps；最低支持档稳定 30fps，评分时间轴独立于渲染 |
| 连续游玩 | 最低机型连续 30 分钟，无明显热降频导致的识别或同步失效 |
| 本地网络 | 检查抖动、丢包、断连；不能只用平均延迟评估 |

先降低粒子与背景复杂度，再降低角色细节，再调整识别输入分辨率；若关键识别不达标，暂停并推荐已认证的配置，不能在后台丢弃动作让玩家连续 Miss。调整输入规格后需要重新确认算法精度。

评分窗口一旦随硬件档调整，必须形成独立规则版本或辅助配置，不能隐式放宽后继续与同榜成绩比较。

## 14｜异常、安全与隐私

| 情况 | 产品行为 |
|---|---|
| 暗光、逆光、关键关节遮挡 | 指出问题部位，提示补光或调整站位；持续异常暂停 |
| 未授权摄像头 | 解释用途，进入设置或返回主入口 |
| 手机移动、旋转或画面裁切变化 | 暂停并重校准；不能把相机移动当 Z |
| 其他人经过 | 保持原玩家 ID；不明确时暂停，不自动换玩家 |
| 玩家出框 | 快速提示回到框内；持续则暂停 |
| 太近、太远或手臂将出框 | 站位提示；不通过放宽阈值硬开局 |
| Z 连续误触发/识别失败 | 停止 Z 正式计分，提示重校准或重开原地版 |
| 通知、电话、应用后台或音频焦点丢失 | 暂停并冻结时间轴；返回后重新确认连接与同步 |
| 曲目下载损坏 | 校验失败不可开始；重试或播放其他已安装曲目 |
| 存档失败 | 保留本局结算并允许重试保存，避免重复写入 |

安全动作边界：无需跳跃或冲刺；不以速度和步幅越大分越高；前后律动保持小幅，面对屏幕。长歌单之间提供休息位，连续游玩约 15 分钟给一次可关闭的休息提醒。

隐私默认：图像在手机本地处理，不上传、不默认录像，不做人脸身份识别；玩家档案用本地昵称和角色。若启用本地预览传输，仅在当前配对会话内传送。错误日志默认记录事件与性能数值，不包含原始视频或完整人体轨迹；采集测试视频须单独明确告知并获得同意。支持删除本地档案与纪录。

## 16｜多人扩展要求

### 16.1 首发轮流派对

同一首同一段落、同一难度、同一动作配置和评分版本才能直接排名。换人重新校准个人触达区，不改评分窗口。记录玩家昵称、成绩与轮次，可快速重试。
不同难度允许自由游玩，但结算只分别展示成就，不按归一化百分比分出同条件胜负。

### 16.2 后续双人同屏门槛

- 算法能同时稳定跟踪两个人，分别维护动作状态、归一化范围、Z 冷却和评分。
- 采用固定左右物理区域，检测身份交换、跨区和相互遮挡；不明确时保护暂停。
- 有足够的横向与前后空间，不能只因两个人静止入框就开启纵深谱面。
- 双人默认先用原地版；Z 必须单独通过双人误触发和空间测试后开放。
- 一人失踪或网络故障时整体暂停，合作分数和个人分数不能继续不对称累计。
- 双人角色和特效在各自分屏内；分屏后文字、目标大小仍通过电视观看测试。
